# 主流预处理正在改写行范数的含义

2023–2026 年，计数型数据（scRNA-seq、测序型与成像型空间转录组）的默认转换仍是**先按 size factor 缩放，再取 log(y/s+1)**。Scanpy 用 `normalize_total` 把每个细胞缩放到中位深度再 `log1p`，Seurat v5 用 `LogNormalize`（scale.factor 1e4），Bioconductor 用 `logNormCounts`（log2，伪计数 1）。这一步的输出稀疏、非负，但几乎所有工具随后都把 **kNN 图建在 10–50 个主成分上**，而主成分是稠密、带符号的。蛋白数据（CyTOF、流式、光谱流式、IMC、MIBI）的默认是**逐通道、不居中的 arcsinh**：CyTOF 的 cofactor 5 仍硬编码在 CATALYST、Spectre、diffcyt 里，聚类前也不做缩放。对 CosTaL+ 来说，关键在行范数。Tanimoto 恒等于 cos/(r + 1/r − cos)，相对 cosine 多出的信息只来自范数比 r。按这个判据看各类转换：**在所有输入中，蛋白数据的 arcsinh 是行范数最干净地等于"总体标志物丰度"的一类**；计数数据经 shifted log 后，行范数混合了表达谱集中度和残余测序深度；PCA、Pearson residuals、z-score 之后，行范数变成"离数据中心有多远"；scGPT、UCE、SCimilarity 的嵌入已经单位化，Tanimoto 在上面退化为 c/(2−c)。原版 CosTaL 的 scRNA-seq 预处理在 `log1p` 之前不做 `normalize_total`，现行默认里没有一家这样做。这样得到的行范数主要记录测序深度，Tanimoto 会把这份技术变异放大成边权差异；补一行 `normalize_total(target_sum=None)` 即可修正，而且不损失稀疏性。空间数据则提醒另一面：库大小会随组织结构变化（Bhuva 2024）；小面板上做 total-count 归一化，结果又取决于面板怎么设计（Atta 2024）。幅度在这里既是真实信号，也是真实混杂。因此后端应按"输入类"分派，而不是按平台：保零、非负的变换走稀疏倒排索引；任何居中的表示，以及全部基础模型嵌入，都走稠密后端。

## 每种转换都归结为一个问题：r 代表什么

记 c 为 cosine，r = ‖a‖/‖b‖，则 Tanimoto 可以改写为 **T = a·b/(‖a‖²+‖b‖²−a·b) = c/(r + 1/r − c)**（本报告自行推导；几份调研笔记各自独立得到了同一个式子）。由于 r + 1/r ≥ 2，只在两个向量等长时取等号，所以 cosine 固定时 T 在 r = 1 处最大，范数相差越大，T 被压得越低。当 r 恒为 1 时，T = c/(2−c) 是 c 的严格单调函数，邻居排序与 cosine 完全相同。分母恒满足 ‖a‖²+‖b‖²−a·b ≥ (‖a‖²+‖b‖²)/2 > 0，带符号的输入因此不会除零，但 T 的取值范围会从非负输入时的 [0, 1] 扩大到 **[−1/3, 1]**（b = −a 时取到 −1/3）。原版 CosTaL 正好把这两面拆开处理：`find_communities` 用 L2 归一化后的 X 选邻居，`build_tani_graph` 用未归一化的 X 算边权。在 Levine_32dim 上，行范数跨度为 5.8 倍，原版 T 与退化形式 c/(2−c) 最多相差 0.516，可见幅度确实在起作用（[docs/01 §2.2](../docs/01_技术规划.md)）。

第二个推论决定了"选哪种归一化"在 CosTaL+ 里的地位：**cosine 对正的逐行缩放不变**。原始计数、total-count 归一化、按细胞面积或体积归一化、Xenium Onboard Analysis 的 size factor、不取 log 的 CPM，本质上都只是给每一行乘一个正数，因此产生**完全相同的 cosine kNN 图**。只有在后面接了非线性的逐元素变换（log1p、sqrt），或者逐基因的变换（z-score、Pearson residuals、PCA）时，邻居集才会改变。所以线性归一化选哪种，只影响 Tanimoto 那一步，实际上是在回答"让行范数代表什么"。下文对每类数据都问同样三件事：输出是否稀疏、能否为负、行范数还剩什么生物学含义。

## scRNA-seq：shifted log 仍是基准，原版 CosTaL 少了一步

三大生态在 2025–2026 年的默认做法一致，都是先除以 size factor 再取 log，伪计数为 1。Scanpy 的 `normalize_total` 默认 `target_sum=None`，即把每个细胞缩放到**所有细胞总计数的中位数**，然后 `log1p`（[scanpy normalize_total](https://scanpy.readthedocs.io/en/stable/generated/scanpy.pp.normalize_total.html)）。Seurat v5.6 的 `NormalizeData` 默认 `LogNormalize`、`scale.factor = 10000`、自然对数（[Seurat NormalizeData](https://satijalab.org/seurat/reference/normalizedata)）。scuttle 的 `logNormCounts` 默认 log2、`pseudo.count = 1`，并把 size factor 居中到 1；OSCA 的示例代码用 scran pooling 估计 size factor（[scuttle logNormCounts](https://rdrr.io/bioc/scuttle/man/logNormCounts.html)；[OSCA basic](https://bioconductor.org/books/release/OSCA.basic/normalization.html)）。另一条路线是 Pearson residuals。Scanpy 的解析版本到 1.12.4 仍放在 `sc.experimental` 下，θ = 100，clip 到 ±√n（[scanpy normalize_pearson_residuals](https://scanpy.readthedocs.io/en/stable/generated/scanpy.experimental.pp.normalize_pearson_residuals.html)）。Seurat v5 的 `SCTransform` 默认用 v2 flavor，`scale.data` 里存的是居中后的 residuals，默认 3,000 个变量基因，直接送进 PCA（[Seurat SCTransform](https://satijalab.org/seurat/reference/sctransform)）。还有一个细节与 CosTaL+ 的确定性目标直接相关：直到 Scanpy 1.12.4（2026-08-27）才修复了一个 bug，即 `target_sum=None` 时**稀疏输入和稠密输入算出的 target_sum 不同**（[Scanpy release notes](https://scanpy.readthedocs.io/en/stable/release-notes/index.html)）。"同一份数据换一种存储格式，结果就不一样"这种事，在主流工具里确实发生过。

这一领域的参照基准仍是 Ahlmann-Eltze & Huber（Nature Methods 2023）。他们比较了四个家族的 22 种转换，结论是 **log(y/s + y0) 加 PCA 的效果与 residual 类、潜在表达类和计数因子模型类方法持平或更好**；而且 delta-method 类转换保留稀疏性，最省内存（[Ahlmann-Eltze & Huber 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10172138)）。他们把伪计数和过度离散联系起来（y0 = 1/(4α)）：对约 5,000 UMI 的细胞用 CPM，相当于 α = 50，比典型单细胞数据大两个数量级；Seurat 的 1e4 则相当于 y0 ≈ 0.5。因此，**不要把 CPM 喂给 shifted log**。对 CosTaL+ 更重要的是另外两条结果。第一，在只含技术变异的均质 RNA 液滴数据上，**做完缩放之后，size factor 仍是一个强方差成分**。第二，按"变换后各基因之和"再做一次逐细胞缩放，既去不掉深度混杂，也不提高 kNN recall，作者明确反对这样做（同上）。Heumos 等人的 scverse 最佳实践按任务给建议：shifted log 用于降维和 DE，scran 用于批次校正，解析 Pearson residuals 用于选 HVG 和找稀有细胞；同样警告不要用 CPM（[Heumos et al. 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10066026)）。2024–2026 年没有高影响力的基准推翻这个结论。Ge 等人（PLOS ONE 2025）在 10x 数据的 ARI 聚类上偏向 Dino（[Ge et al. 2025](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0335102)），但他们按标签算 ARI，Ahlmann-Eltze & Huber 比的是 kNN 重叠，两者不能直接对比。Pachter 组的 PFlog1pPF（一种 shifted CLR）声称在 Ahlmann-Eltze & Huber 的 kNN 基准上表现更好，但目前仍是未经同行评审的预印本（[bioRxiv](https://www.biorxiv.org/content/10.1101/2022.05.06.490859v4.full)）。

还要说清楚 kNN 图建在什么表示上。Scanpy 的 `pp.neighbors` 在变量数不少于 50 时默认用 50 个主成分，`metric='euclidean'`，`n_neighbors=15`，数据量大时走 PyNNDescent 近似搜索（[scanpy neighbors](https://scanpy.readthedocs.io/en/latest/api/generated/scanpy.pp.neighbors.html)）。Seurat 的 `FindNeighbors` 默认 `dims = 1:10`、`k.param = 20`、annoy 近似搜索、Euclidean 距离（[Seurat FindNeighbors](https://satijalab.org/seurat/reference/findneighbors)）。Heumos 等人明确写道，聚类作用于在低维表示上计算的 KNN 图（[Heumos et al. 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10066026)）。Ahlmann-Eltze & Huber 的正面结论只在"合理的 PCA 维数范围"内成立，所以**原版 CosTaL 在 2,000 个 HVG 上做基因级稀疏 cosine kNN，已经超出 shifted log 被验证过的设定**。这并不等于做法错误。merfish-tools 对约 500 个基因的 MERSCOPE 面板就直接用 `use_rep="X", metric="cosine"` 建图（[merfish-tools](https://merfish-tools.readthedocs.io/en/latest/notebooks/analyze_merscope_experiment.html)）；jvecfor 的 Bioconductor 文档也建议，对于库大小抬高了范数的 log-normalized 计数用 cosine（[jvecfor vignette](https://bioc-release.r-universe.dev/jvecfor/doc/jvecfor_vignette.Rmd)）。但 2023–2026 年没有任何单细胞基准定量比较过 cosine 和 Euclidean，也没有基准比较过基因级的图和 PCA 上的图。

原版 `pp(X, 'scrnaseq')` 的实际步骤是 `filter_cells(min_genes=200)` → `filter_genes(min_cells=3)` → `highly_variable_genes(n_top_genes=2000, flavor='seurat_v3')` → `log1p` → 取 HVG 子集（[clustering.py](../bench/reference/CosTaL-0.0.2.4/CosTaL/clustering.py)）。其中在原始计数上用 `seurat_v3` 选 HVG 是正确用法（[scanpy highly_variable_genes](https://scanpy.readthedocs.io/en/stable/generated/scanpy.pp.highly_variable_genes.html)），问题出在 `log1p` 之前没有任何 size factor。调研没有找到任何 2023–2026 年的来源支持"不做 size factor、直接 log1p"再去聚类。Ahlmann-Eltze & Huber 也只把 y 和 y/s 当作负对照：在 SUM149PT 上，最佳方法 50 个邻居能对上 34 个，负对照只有 9 个；他们没有测 log(y+1)（[Ahlmann-Eltze & Huber 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10172138)）。从机制上看，深度变为 k 倍时，已检出基因各自约增加 log k，同时被检出的基因变多，行范数沿这两条路单调上升。log1p 又不是齐次函数，深度变化还会把向量方向往 0/1 检出模式上拧，所以**在这种输入上 cosine 也不是深度不变的**。Hicks 等人报告过同一现象：检出率与前两个主成分相关，足以把同一个肿瘤按批次拆成两簇（[Hicks et al.](https://www.biorxiv.org/content/10.1101/025528v4.full)）。Hafemeister & Satija 也在 log-normalized 数据的簇内看到了沿深度排列的梯度（[Hafemeister & Satija 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6927181/)）。在这种输入上，Tanimoto 多出来的信息基本是技术性的：同一类型、一深一浅的两个细胞之间的边会被 r + 1/r 压低，可能沿深度把簇拆开，或者把浅测序的细胞推到簇的边缘。修复只需一行：在 `log1p` 前插入 `normalize_total(target_sum=None)`（或 scran 的 size factor）。深度归一化和 log 都不改变零（[Lause et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8419999/)），稀疏后端可以照常使用。

| 转换（2023–26 现状） | 稀疏 | 可负 | 行范数编码什么 |
|---|---|---|---|
| log1p(y)，无 size factor（**原版 CosTaL**；没有现行默认采用） | 是 | 否 | 随深度单调上升：检出基因更多，每个非零项约多 log k；深度还会改变方向 |
| y/s（CPM、Seurat RC，不取 log） | 是 | 否 | L1 固定；L2 等于表达谱集中度，低深度时偏高 |
| **log(y/s+1)**（Scanpy 中位数 / Seurat 1e4 / scuttle log2；**现行默认**） | 是 | 否 | 未归一化；集中度（少数 marker 占主导）与残余深度混在一起，二者不可分 |
| log(CPM+1) | 是 | 否 | 被检出模式主导；Ahlmann-Eltze & Huber、Heumos 均反对 |
| shifted log ÷ 每细胞变换后的总和 | 是 | 否 | L1 固定，幅度被抹掉；Ahlmann-Eltze & Huber 反对 |
| SCT `data` = log1p(校正后计数) | 是 | 否 | 类似 shifted log，残留的深度更少 |
| 解析 Pearson residuals / SCT v2 `scale.data` | **否**（没有零） | **是** | 偏离全局平均谱的程度（以噪声为单位），相对于该数据集而言 |
| z-score（`ScaleData`、`sc.pp.scale`） | 否 | 是 | 离数据中心的对角 Mahalanobis 距离 |
| PCA 30–50 维（**实际的 kNN 输入**） | 否 | 是 | 主成分子空间里离中心的距离；PC1 若跟着深度走，范数里就含深度 |

即使加了 size factor，shifted log 的行范数也不"只剩生物学"：它是表达集中在少数 marker 上的程度（生物学）与残余深度、检出率（技术）的混合，单凭计数无法拆开。调研没找到任何研究量化过两者的比例，这需要 CosTaL+ 自己测。

## 空间转录组：库大小一半反映组织结构，一半是测量几何的产物

### 测序型平台：库大小本身就是组织结构的读数

各厂商的流程交出来的都是原始整数 UMI 矩阵，包括 Space Ranger 的 2/8/16 µm bin 和 v4 的细胞分割输出、Stereo-seq 的 GEF、Slide-seq/Curio 的 bead。社区默认的做法是全局库大小缩放加 log1p。Seurat 的 Visium HD 教程（按 bin 和按细胞分割两版）都写明"standard log-normalization"，取代了旧 Visium/Slide-seq 教程里的 SCTransform（[Seurat Visium HD](https://satijalab.org/seurat/articles/visiumhd_analysis_vignette)；[Seurat 细胞分割](https://satijalab.org/seurat/articles/visiumhd_analysis_cell_segmentations)；[旧版空间教程](https://satijalab.org/seurat/articles/spatial_vignette)）。Stereopy 的快速入门是 `normalize_total(target_sum=10000)` → `log1p` → `scale(max_value=10, zero_center=True)` → 30 个主成分 → Leiden（[Stereopy](https://stereopy.readthedocs.io/en/latest/Tutorials/SquareBin_Clustering.html)）。Giotto 的默认 "standard" 方法是 scalefactor 6000、log2(x+1)，再按基因和按细胞各做一次 z-score（[normalizeGiotto](https://giottosuite.com/reference/normalizeGiotto.html)）。BANKSY 则特立独行：`normalizeCounts(log = FALSE)` 只缩放到平均库大小，不取 log（[BANKSY](https://github.com/prabhakarlab/Banksy)）。空间域识别方法吃的也大多是 log-normalized 的 HVG：STAGATE 用 `normalize_total(1e4)` + `log1p`，SpaGCN 用 `normalize_per_cell` + `log1p`（[STAGATE](https://stagate.readthedocs.io/en/latest/T1_DLPFC.html)；[SpaGCN](https://github.com/jianhuupenn/SpaGCN/blob/master/tutorial/tutorial.md)）。GraphST 用 `scale(zero_center=False)`，只做除法，所以仍保持稀疏和非负，但随后在 `get_feature` 里把矩阵转成了稠密（[GraphST preprocess.py](https://github.com/JinmiaoChenLab/GraphST/blob/main/GraphST/preprocess.py)）。

这一领域最重要的新证据来自 Bhuva 等人（Genome Biology 2024）。他们分析了 4 个平台的 25 个样本，发现库大小随皮层分层、白质、肿瘤区域而变化：泊松模型扣除细胞数之后，**组织区域对库大小仍然显著（p < 2×10⁻³⁰⁸）**。在空间域识别上，sctransform 通常最差，"不归一化"（log 原始计数）和 scran 最好。作者的原话是，空间数据 "should not be specifically corrected for library size prior to analysis"（[Bhuva et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11025268/)）。随后的 SpaNorm（Genome Biology 2025）用薄板样条把空间平滑变异拆成"与库大小有关"和"与库大小无关"两部分，只保留后者，在 4 个平台的 27 个样本上优于常见的单细胞归一化；它输出 `logpac`、`pearson`、`meanbio` 等几种形式（[SpaNorm](https://genomebiology.biomedcentral.com/articles/10.1186/s13059-025-03565-y)；[SpaNorm vignette](https://bioconductor.org/packages/release/bioc/vignettes/SpaNorm/inst/doc/SpaNorm.html)）。但 iMeta 2025 的大型基准（14 种方法、约 600 个数据集）得出的结论是"normalization was indispensable"，推荐的流程是库大小归一化、log、3,000 个空间变异基因、不标准化、20 个主成分（[iMeta 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12747554/)）。两者的分歧可能来自评测对象不同。Bhuva 用的是 DLPFC 这类人工标注的空间域，那里库大小本身就是一个区分特征；iMeta 则在大多为深度学习的方法上取平均。这一判断是推断，调研没有找到直接解开这一冲突的研究。

在稀疏度上，Visium HD 的 2 µm 方格是连续铺开的，8 µm bin 的平均 UMI 约为 2 µm 的 16 倍，也是 10x 推荐的起点（[Oliveira et al. 2025](https://www.nature.com/articles/s41588-025-02193-3)）。一行有 U 个 UMI，最多就只有 U 个非零基因，所以零比例 ≥ 1 − U/G（自行推导）。以 OSTA 的 CRC 数据为例（G ≈ 18,085；8 µm bin 的 QC 下限是库大小 100）：**库大小刚过 QC 下限 100 的 8 µm bin 零比例至少 99.45%（300 UMI 时至少 98.3%），2 µm 在 99.9% 以上，分割出的细胞（约 300–1,400 UMI）约为 92–98%**（[OSTA Visium HD bin](https://bioconductor.org/books/release/OSTA/pages/seq-workflow-visium-hd-bin.html)；[OSTA Visium HD 分割](https://bioconductor.org/books/release/OSTA/pages/seq-workflow-visium-hd-seg.html)）。这些是数学下界，不是实测中位数。从 bin 到细胞有两个常用工具：bin2cell 先按行列分位数做去条纹，再逐 bin 缩放（[bin2cell](https://pmc.ncbi.nlm.nih.gov/articles/PMC11419951/)）；ENACT 按面积或转录本加权分配（[ENACT](https://academic.oup.com/bioinformatics/article/41/3/btaf094/8063614)）。两者都会产生非整数计数，而去卷积这一步又必须用未归一化的原始计数（[cell2location](https://cell2location.readthedocs.io/en/latest/notebooks/cell2location_tutorial.html)）。

### 成像型平台：小面板让 total-count 归一化取决于面板怎么设计

Atta 等人（Genome Biology 2024）给出了机制。在偏向某些区域的标志物面板里，过度代表的基因会抬高该区域细胞的库大小 scaling factor，把那里的归一化表达压低，同时抬高别处。结果是 DE 错误率在 MERFISH 上**最高 13%，在某些模拟面板上最高 30%**；跨数据集的倍数变化方向翻转**最高 60%**；CosMx 上 SVG 假阴性最高 24%。面板扩到 5,000 个基因时效应变小，但仍然存在。细胞体积与检出了哪些基因无关，所以作者把**按体积归一化列为首选**，面积可以作为替代，前提是分割可靠（[Atta et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11167774/)）。

厂商与社区的做法分成几条线。Xenium Onboard Analysis 的 size factor 是"细胞总转录本数 ÷ 所有细胞的中位数"，聚类在 10 维 PCA 空间里进行，UMAP 用 `metric="pearson"`（[10x XOA](https://www.10xgenomics.com/support/software/xenium-onboard-analysis/latest/algorithms-overview/gex-secondary-analysis-algorithms)）。Bruker 的 AtoMx 推荐 Total Counts；Pearson residuals 只建议用于 50 万细胞以下的数据；用 50 个主成分，UMAP 用 Cosine 距离（[Bruker blog](https://brukerspatialbiology.com/blog/tips-when-performing-cosmx-data-analysis-with-atomx-sip/)）。Danaher 的 Scratch Space 明确建议保持线性尺度，并给作除数的总计数设了 20 的下限，以限制对低计数细胞的放大，同时承认这样做会丢掉"癌细胞整体 RNA 更多"这一真实生物学信号（[CosMx Scratch Space](https://nanostring-biostats.github.io/CosMx-Analysis-Scratch-Space/posts/normalization/index.html)）。Seurat 对 Vizgen 和 CosMx 用 `SCTransform(clip.range = c(-10, 10))`，接 30 个主成分（[Seurat 成像空间教程](https://satijalab.org/seurat/articles/seurat5_spatial_vignette_2)）。Squidpy 的 Xenium 和 Vizgen 教程是 `normalize_total` + `log1p` + PCA + Leiden，只在文字里提了一句"也可以按体积归一化"（[Squidpy Xenium](https://squidpy.readthedocs.io/en/stable/notebooks/tutorials/tutorial_xenium.html)；[Squidpy Vizgen](https://squidpy.readthedocs.io/en/stable/notebooks/tutorials/tutorial_vizgen.html)）。真正采用面积 size factor（`cell_area / median(cell_area)`）的只有 Bioconductor 的 OSTA（[OSTA Xenium](https://lmweber.org/OSTA/pages/img-workflow-xenium.html)；[OSTA CosMx](https://lmweber.org/OSTA/pages/img-workflow-cosmx.html)）。Salas 等人（Nature Methods 2025）在 25 个 Xenium 数据集上做了基准，最优流程是"库大小归一化到 100、取 log、缩放、用全部主成分建 16 近邻图、Louvain"，并且发现归一化方法是整个处理流程里最关键的因素之一（[Salas et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11978515/)）。

分割会同时改变分子（分配到细胞的计数）和分母（面积）。按 Proseg 论文的测量，厂商默认分割会留下 20% 以上的转录本未分配；MERSCOPE 上 T 细胞的中位数只有 81 个转录本，肿瘤细胞 291 个；用默认分割时，Xenium 肺数据里 37% 的 DE 结果可疑，换成 Proseg 后降到 12%（[Proseg](https://pmc.ncbi.nlm.nih.gov/articles/PMC11071468/)）。Mitchel 等人（Nature Genetics 2026）发现，分割错误带来的影响经常主导 DE 和配体–受体分析的结果（[Mitchel et al.](https://www.biorxiv.org/content/10.1101/2025.01.02.631135.full.pdf)）。邻居细胞的污染是**加性**的：它给向量叠加了邻居的表达谱，既转动方向、也改变范数，任何逐细胞的标量归一化（无论是 total-count 还是面积）都去不掉。这一点是推断，与 Danaher 所说的"加协变量只能缓解、不能解决"一致（[segmentation-error 帖](https://nanostring-biostats.github.io/CosMx-Analysis-Scratch-Space/posts/segmentation-error/index.html)）。稀疏度可以由每个细胞的计数和面板大小来估：CosMx 6K 淋巴结数据平均每细胞 461 个基因，约 92% 为零（[NanoString 数据页](https://nanostring.com/wp-content/uploads/2024/11/MK6578_CosMx_Human_Lymph_Node_FFPE_Dataset_webpage.html)）；CosMx WTx 每细胞 627–1,677 个基因，约 91–97% 为零（[Bruker WTx](https://brukerspatialbiology.com/blog/moving-beyond-scrna-seq-the-power-of-cosmx-whole-transcriptome/)；[AACR 2025 海报](https://nanostring.com/wp-content/uploads/2025/05/2779-AACR-2025_WTX_Cell_Assay_MerckBruker_Yi-Cui_MSedits_HS.pdf)）。300–500 基因的小面板没有找到公开的零比例，按每细胞约 100–400 个计数推算，约为 60–85%。

| 转换（典型场景） | 稀疏 | 可负 | 行范数编码什么 |
|---|---|---|---|
| 原始计数（各厂商导出；去卷积；InSituType） | 是：Visium HD 2 µm ≳99.9%，8 µm 约 98–99.5%；小面板约 60–85%；5K/6K/WTx 约 85–97% | 否 | 每个 bin 里的细胞数、所在区域（Bhuva）、细胞大小、RNA 含量 × 捕获/透化/检出效率 × 分割污染 |
| total-count 线性（AtoMx Total Counts、XOA size factor、BANKSY `normcounts`） | 与原始相同 | 否 | L1 固定；L2 = S·√Σp²，即集中度，**取决于面板设计** |
| 面积/体积线性（Atta 首选） | 与原始相同 | 否 | 每 µm² 的转录本密度，会继承分割误差 |
| log1p(total-count × L)（Seurat、Scanpy/Squidpy、Stereopy 1e4、Salas 用 L = 100） | 与原始相同 | 否 | 残余深度/基因数 + 集中度 |
| log(面积归一化 + 1)（OSTA） | 是 | 否 | 经压缩的转录本密度 |
| SCT residuals、解析 Pearson、SpaNorm `pearson` | **稠密** | **是**（Seurat 成像数据 clip ±10） | 偏离期望值的程度；低深度细胞仍带深度 |
| z-score（Giotto 默认的末步、Stereopy `zero_center=True`、Salas 最优流程） | 稠密 | 是 | 离数据中心的距离 |
| GraphST `scale(zero_center=False)` | 是 | 否 | 同 log1p，只是对基因重新加权 |
| PCA、BANKSY PCs、GNN 隐空间 | 稠密 | 是 | 离数据中心的距离 |
| bin2cell / ENACT / Proseg 期望计数 | 是（Proseg 期望计数可能零更少，未核实） | 否（非整数） | 细胞大小 + 残余捕获差异 |

对 CosTaL+ 而言，空间数据的特殊之处在于幅度"有信息"和"被混杂"同时成立。在测序型平台上，原始计数或 log 原始计数的行范数随每个 bin 的细胞数和所在区域变化，Tanimoto 会偏向**空间域**的划分，而这正是库大小归一化要去掉的东西。在成像型平台上，面积归一化后的行范数等于转录本密度，是最接近"RNA 含量"的量，但它的可靠程度不会超过分割。

## 蛋白数据：arcsinh 后不缩放直接聚类，幅度保留得最完整

悬浮细胞术里，CyTOF 的 cofactor 5 仍是硬编码默认值。CATALYST 的 `prepData` 签名就是 `cofactor = 5`，并接受按通道给出的向量（[CATALYST prepData.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/prepData.R)）；Spectre 的 `do.asinh` 默认也是 5（[Spectre do.asinh.R](https://github.com/ImmuneDynamics/Spectre/blob/master/R/do.asinh.R)）；diffcyt 说 5 "适合 CyTOF"（[diffcyt](https://rdrr.io/bioc/diffcyt/man/transformData.html)）。CytoNormPy 的基准和 Open Problems 2026 的细胞术批次整合基准也都用 cofactor 5 处理 CyTOF（[CytoNormPy](https://onlinelibrary.wiley.com/doi/10.1002/cyto.a.24953)；[Open Problems](https://openproblems.bio/benchmarks/cyto_batch_integration)）。但 Spectre 自己的文档写着"对多数 CyTOF 通道，15 合适"（[Spectre 文档](https://immunedynamics.io/Spectre/articles/data_transformation.html)）。**CosTaL 的 5/150/6000 三元组与 cyCombine 文档里的推荐值完全一致**（[cyCombine](https://pmc.ncbi.nlm.nih.gov/articles/PMC8971492/)）。这些值是工具之间互相继承的约定，没有一个是独立验证过的最优值。光谱流式的 6000 另有一处出处：Jaimes 等人在 OMIQ 里比较 Aurora 与 CyTOF 时，选 6000 是为了"让阴性群在 0 附近呈单峰"（[Jaimes et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9790709/)）。但对传统流式和光谱流式，公认的最佳实践是**逐通道调 cofactor，范围 10–10,000**（[den Braanker et al. 2021](https://www.frontiersin.org/journals/immunology/articles/10.3389/fimmu.2021.768113/full)）。OTflow、flowVS 等工具能自动估计逐通道 cofactor（[OTflow](https://onlinelibrary.wiley.com/doi/full/10.1002/cyto.a.24491)），但调研没有找到 2023–2026 年有哪种新方法取代了它们。对光谱数据统一用一个 cofactor，意味着一些通道被过度压缩、另一些压缩不足，这会改变哪些 marker 主导行范数。另一个陷阱是 logicle：它是 FlowJo 显示时的默认，也是 FlowSOM `ReadInput` 的默认 `transformFunction`（但默认 `transform = FALSE`）（[FlowSOM](https://github.com/SofieVG/FlowSOM/blob/master/R/0_FlowSOM.R)）。按定义，数据值 0 在 logicle 下不映射到 0，所有细胞会共用一个正的偏移向量，cosine 的原点因此失去"无信号"的含义。这一点调研没有用 flowCore 实测核实，应先测一次再决定是拒收 logicle 输入还是重新居中。

负值方面，主流 CyTOF 流程默认保留负值。diffcyt 解释了来源：仪器软件默认会做背景扣除，并把整数计数随机化（[diffcyt](https://rdrr.io/bioc/diffcyt/man/transformData.html)）。Papoutsoglou 等人测得，最大程度的随机化会让元聚类的 ARI 从 0.83 降到 0.72（[Papoutsoglou et al. 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC7027760/)）。CATALYST 的 `compCytof` 默认用 NNLS 补偿，输出天然非负（[compCytof.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/compCytof.R)）。Spectre 的 `reduce.noise`（减 1、负值替换为小噪声）是显式标注为"实验性"的可选项。原版 CosTaL 有一个对应的可选函数 `minus_1_normalize_arcsinh`：先减 1、在 0 处截断、把全零行填成 1.0，再做 arcsinh（[clustering.py](../bench/reference/CosTaL-0.0.2.4/CosTaL/clustering.py)）。全零行填 1.0 避免了 cosine 无定义，但会把这些细胞放到同一个均匀方向上。在本仓库的 Levine_32dim 数据上实测：原始值里 27.0% 为负，范围在 [−0.291, 0)，没有精确的零；经 arcsinh(x/5) 后负值落在 [−0.058, 0)，**只占每个细胞平方范数的约 0.01%**，截断到 0 会把非零比例从 100% 降到 73%（[Levine_32dim_notransform.fcs](../bench/data/Levine_32dim_notransform.fcs)）。所以在 CyTOF 上，留不留负值是密度和性能问题，不涉及语义。流式和光谱流式经补偿或解混后，负值在原始单位下可达数百到数千，在阴性群两侧对称分布，截断会在 0 处堆积质量。这一点是推断，没有实测。

聚类前不缩放，也是主流做法。FlowSOM 默认 `scale = FALSE`，CATALYST 的 `cluster()` 直接把 `exprs` assay 送进 FlowSOM（[CATALYST cluster.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/cluster.R)），0–1 的百分位缩放只用在热图上。批次校正在 arcsinh 尺度上进行，输出也在这个尺度上：CytoNorm 2.0 不再需要技术重复样本（[CytoNorm 2.0](https://pure.eur.nl/en/publications/cytonorm-20-a-flexible-normalization-framework-for-cytometry-data/)）；cyCombine 只把 z-score 或秩当作 SOM 共聚类的中间量，ComBat 在原始表达尺度上做，结果再截到输入范围（[cyCombine](https://pmc.ncbi.nlm.nih.gov/articles/PMC8971492/)）。也就是说，**CosTaL 的蛋白预处理与 CATALYST、Spectre、FlowSOM 的默认对齐**，行范数就是总体标志物丰度。

空间蛋白组的流程更分散，大致分成保留幅度和抹掉幅度两类。IMC 的 Bodenmiller 流程是：steinbock 取每个细胞像素的**均值**，CATALYST 用 NNLS 做溢出补偿，再做 **asinh(x/1)**，之后不缩放直接聚类（[steinbock](https://github.com/BodenmillerGroup/steinbock/blob/main/docs/cli/measurement.md)；[IMCDataAnalysis](https://bodenmillergroup.github.io/IMCDataAnalysis/read-data.html)；[phenotyping](https://github.com/BodenmillerGroup/IMCDataAnalysis/blob/main/08-phenotyping.Rmd)）。独立的 OPTIMAL 研究在 cofactor 0.1–150 之间滴定，结论是 1 最优，并建议之后再做 z-score 去批次（[OPTIMAL 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC10952805/)）。注意 IMC 书里整合后的聚类是在 fastMNN 嵌入上做的，而 fastMNN 默认 `cos.norm = TRUE`，会先把每个细胞 L2 归一化（[batchelor fastMNN.R](https://github.com/LTLA/batchelor/blob/master/R/fastMNN.R)）。MIBI 的 ark 流程是 total intensity ÷ 细胞面积，再做 arcsinh(100·x)（[ark](https://github.com/angelolab/ark-analysis/blob/main/src/ark/segmentation/marker_quantification.py)）。Pixie 则先把每个像素归一化到和为 1，再用 99.9 百分位缩放，作者明确承认这样**无法发现以同一 marker 表达高低区分的表型**（[Pixie](https://pmc.ncbi.nlm.nih.gov/articles/PMC10393943/)），这是"逐行归一化抹掉水平信息"的直接证据。CODEX 的 SPACEc 默认对每个 marker 做 z-score，沿用了 Hickey 2021 的推荐（[SPACEc](https://github.com/yuqiyuqitan/SPACEc/blob/master/src/spacec/preprocessing/_general.py)；[Hickey et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8415085/)）。CyCIF 的 scimap 是 log1p 加上以 GMM 门为锚、逐图像分段缩放到 [0, 1]（[scimap](https://scimap.xyz/Functions/pp/rescale/)）。spatialproteomics（Nature Methods 2026）默认 arcsinh(x/5)（[spatialproteomics](https://github.com/sagar87/spatialproteomics/blob/main/spatialproteomics/pp/utils.py)）。基准之间互相矛盾：Hickey 推荐 z-score；UniFORM 指出，在右偏的数据上 z-score 会把低强度的点压缩到 0 附近，并削弱 marker 之间的互斥关系（[UniFORM 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12539234/)）。没有一个基准评估过行范数本身是否有用。

各种转换究竟如何改变行范数的含义，可以直接在 Levine 上量出来。下表中，"丰度"定义为 Σ asinh(max(x,0)/5)，ρ 为细胞行范数与之的 Spearman 相关（[Levine_32dim_notransform.fcs](../bench/data/Levine_32dim_notransform.fcs)，265,627 个细胞 × 32 个 marker）：

| 转换 | 非零比例 | 负值比例 | ρ(范数, 丰度) | ρ(范数, 原始和) |
|---|---|---|---|---|
| asinh(x/5)，保留负值（CosTaL 默认） | 1.000 | 0.270 | 0.790 | 0.762 |
| asinh(max(x,0)/5)，截断 | 0.730 | 0 | 0.790 | 0.762 |
| asinh(x/1)（IMC 惯例） | 1.000 | 0.270 | 0.968 | 0.544 |
| asinh(x/150)（流式 cofactor 用在 CyTOF 上） | 1.000 | 0.270 | 0.297 | 0.992 |
| asinh(x/5) → 逐 marker z-score | 1.000 | **0.651** | 0.502 | −0.061 |
| asinh(x/5) → 1/99 百分位截断 + min-max | 0.990 | 0 | 0.919 | 0.456 |
| asinh(x/5) → 逐细胞 L1 归一化 | 1.000 | 0.270 | **−0.783** | 0.173 |

结果有三点。第一，cofactor 决定了范数听谁的：cofactor 小时接近 log，范数反映"有多少 marker 处于开启状态"；cofactor 大时接近线性，范数被最亮的几个通道主导。第二，z-score 之后，范数与丰度的相关降到 0.50，与"离均值有多远"的相关是 0.82，**含义从丰度变成了非典型程度**；而且一个整体偏暗的细胞和一个整体偏亮的细胞会得到符号相反的向量。第三，逐细胞归一化之后，范数与丰度反相关，量的是集中度。

## 基础模型：输入端抹掉深度，输出端要么单位化，要么范数无人解释

输入编码分为四个家族。第一类是逐细胞的秩或分位数编码：Geneformer 先用该基因在整个语料库中的表达水平缩放细胞内表达，再排序（[Geneformer](https://huggingface.co/ctheodoris/Geneformer)）；Nicheformer 先归一到 1 万，再除以按技术分别计算的非零均值，然后排序，序列长度 1,500（[Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)）；scGPT 按细胞内非零值的**分位数**分箱，0 单独占一个箱（[scGPT preprocess.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/preprocess.py)）；State SE 取 log fold 排名前 2,048 的基因（[Virtual Cell Challenge](https://huggingface.co/blog/virtual-cell-challenge)）。这一类编码对细胞内的单调变换不变，库大小在输入端就被丢掉了；scGPT 的零样本嵌入路径因此干脆跳过 `normalize_total` 和 `log1p`（[cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)）。第二类是用 MLP 把连续的 log 值投影成向量：CellFM 用 log1p 加 MLP（[CellFM](https://pmc.ncbi.nlm.nih.gov/articles/PMC12092794/)）；scPRINT 用 log2(x+1) 加 MLP，另有一个总计数 token（[scPRINT](https://pmc.ncbi.nlm.nih.gov/articles/PMC12003772/)）；scFoundation 在 `log1p(x/Σx·1e4)` 后附加 log10(总计数) 等两个深度 token（[scFoundation get_embedding.py](https://github.com/biomap-research/scFoundation/blob/main/model/get_embedding.py)）。第三类是 UCE，按表达量加权采样基因，输入要求原始计数（[UCE](https://github.com/snap-stanford/UCE)）。第四类是 TranscriptFormer，直接对原始计数做生成式建模，计数默认在 30 处截断（[TranscriptFormer](https://github.com/czi-ai/transcriptformer)）。有一项受控比较发现，硬分箱在所有指标上都更差，软分箱最好（[Sadalski, ICLR 2026 workshop](https://iclr.cc/virtual/2026/10013720)）。

输出端，所有模型给出的都是**稠密、可以为负的浮点向量**，维度从 128（SCimilarity）到 1,280（UCE）不等，CellFM 的隐藏宽度为 1,536，scFoundation 的默认拼接为 4d 维。对 CosTaL+ 最关键的分界是是否做了单位化：

| 模型 | 细胞嵌入 | 维度 | 官方代码是否单位化 |
|---|---|---|---|
| scGPT | `<cls>` 输出 | 512 | **是**，除以 L2 范数（[cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)） |
| UCE | MLP 解码后的 CLS | 1,280 | **是**，在 `forward()` 里调用 `normalize`（[UCE model.py](https://github.com/snap-stanford/UCE/blob/main/model.py)） |
| SCimilarity | MLP 瓶颈层 | 128 | **是**，"unit length normalized"（[SCimilarity](https://pmc.ncbi.nlm.nih.gov/articles/PMC11864978/)） |
| Geneformer V2-316M | 默认 CLS；"cell" 模式为均值池化 | 1,152 | 否（[emb_extractor.py](https://huggingface.co/ctheodoris/Geneformer/blob/main/geneformer/emb_extractor.py)） |
| scFoundation | 默认拼接 [深度 token, T token, max-pool, mean-pool] | 4d | 否（[get_embedding.py](https://github.com/biomap-research/scFoundation/blob/main/model/get_embedding.py)） |
| Nicheformer | 基因 token 均值，不含上下文 token | 512 | 文中未提及（[Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)） |
| CellFM / TranscriptFormer / State SE / scPRINT | CLS 或均值池化 | 不全有文档 | 未有文档 |

对单位化的嵌入，r ≡ 1，Tanimoto 只是 cosine 的一个固定凸变换，邻居集合和排序都不变。没有单位化的嵌入里，范数代表什么没有人研究过，唯一的直接证据是负面的：Nicheformer 在池化时排除上下文 token，正是因为 modality token 的输出范数很高，会把嵌入拉向模态（[Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)）。scFoundation 的默认拼接直接包含深度 token 的嵌入，它的范数很可能与库大小相关，而且四个块的尺度不同，拼接后的 cosine 会被范数最大的那块主导。这一点是推断。实践中，CELLxGENE Census 的教程直接 `sc.pp.neighbors(adata, use_rep="scgpt")`，不指定度量，即用 Euclidean（[Census 教程](https://chanzuckerberg.github.io/cellxgene-census/notebooks/api_demo/census_embedding.html)）。对单位化的嵌入，Euclidean、cosine、Tanimoto 选出的邻居集合相同；对未单位化的嵌入则不同。调研没找到任何来源讨论过这个差别。

独立基准对零样本嵌入的评价很低。Kedzierska 等人发现，HVG 在所有指标上都胜过 Geneformer 和 scGPT（[Kedzierska et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12007350/)）。Hou 等人 2026 年比较了 13 个模型：PCA 在胃组织数据上 ARI 为 0.65，只有 SCimilarity 以 0.68 超过它；在空间数据上，零样本条件下没有一个模型胜过 PCA（[Hou et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC12803055/)）。Liu 等人在 1,607 个数据集上得到的结论是，性能强烈依赖任务，没有一种方法始终领先（[Liu et al. 2026](https://www.biorxiv.org/content/10.64898/2026.06.18.733285)）。唯一胜出的 SCimilarity 恰好用三元组损失训练、输出单位化，这说明为距离比较而设计的嵌入更适合 kNN 图；但这只是单个基准里的相关性。还有一点与 CosTaL+ 的确定性有关：scGPT 的官方嵌入路径在非零基因超过约 1,200 个时会随机采样基因，分箱时的并列值也随机打破（[cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)），不固定种子时，两次嵌入本身就不一致。

## 对 CosTaL+：按输入类分派后端，把"幅度代表什么"变成显式参数

综合以上各节，所有输入可以归为五类。后端选择和 Tanimoto 是否有意义都由类别决定，与平台无关：

| 输入类 | 代表 | 稀疏 | 可负 | 行范数含义 | 后端 | Tanimoto 的地位 |
|---|---|---|---|---|---|---|
| A 保零、非负、高维 | scRNA shifted log、SCT `data`、log1p(raw)；测序型空间 bin/细胞；5K/6K/WTx 面板的 log1p 或面积归一化 | 是（Visium HD 2 µm ≳99.9%；5K+ 面板约 85–97%） | 否 | 集中度 + 残余深度；原始或面积归一化时是 RNA 含量/密度 | 稀疏倒排索引 | 有信息但被深度/分割混杂，需实测 |
| B 保零、非负、低维 | 300–500 基因的成像面板 | 中等（约 60–85% 零，估计） | 否 | 同 A | 稠密可能更划算，待测 | 同 A |
| C 低维、不居中的丰度 | CyTOF/流式/光谱 arcsinh、IMC asinh(x/1)、MIBI ark、百分位或 min-max 缩放 | 否（Levine 100% 非零） | CyTOF 有但极小；流式/光谱不可忽略 | **总体标志物丰度**（cofactor 决定谁主导） | 稠密 | **符合 CosTaL 设计本意，证据最强** |
| D 居中、带符号 | PCA、Pearson residuals、SCT `scale.data`、z-score、未单位化的 FM 嵌入 | 否 | 是 | 离数据中心的距离；FM 的范数含义未知 | 稠密 | 语义改变，T 可能为负 |
| E 已逐行归一化 | scGPT/UCE/SCimilarity、fastMNN `cos.norm`、Pixie、double z-score、L1/L2 归一化的输入 | 取决于输入 | 取决于输入 | 常数，或只反映谱的形状 | 稠密 | T ≡ c/(2−c)，没有新信息 |

第一，scRNA-seq 的默认路径。`compat="paper"` 必须继续逐位复现 `log1p(raw)`，这是已经定下的契约（[docs/04 §0.0](../docs/04_选择度量与剪枝策略.md)）。在此之外，应该提供一个 `normalize_total(target_sum=None)` + `log1p` 的 scRNA 预设，用 docs/04 §5 的实验比较两者。如果新预设胜出，按版本策略 (b)，改默认值就要跳主版本号（[docs/04 §6.5](../docs/04_选择度量与剪枝策略.md)）。两个预设都保零、非负，都走稀疏后端，切换不影响后端设计。CPM 预设不应该提供。

第二，后端分派。[docs/06 §5.2](../docs/06_跨平台与确定性.md) 现在的规则只看存储格式、非零比例和维度，应再加两个信号：是否存在负值，各列是否居中。任何列居中的输入实际上都是稠密的，应直接走稠密后端，不必再测阈值。在原始基因空间里做 Pearson residuals 是内存陷阱：100 万细胞 × 2,000 基因 × float32 约 8 GB（自行估算），Lause 等人在 PBMC 上就报告过 4.5 GB（[Lause et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8419999/)）。应建议用户先做 PCA，或者干脆用 shifted log。300–500 基因的成像面板落在稀疏和稠密的分界附近，正好可以用来实测 `auto` 的阈值。

第三，输入诊断写进输出元数据。至少记录四项：行范数的变异系数、列均值和列标准差、负值比例、非零比例。行范数 CV ≈ 0 时，把 [docs/04 §0.1](../docs/04_选择度量与剪枝策略.md) 的短路规则从 `normalize=L2` 推广到"输入本身已单位化"，并发出一次警告，说明 Tanimoto 等价于 cosine 的单调变换。列已居中时，警告行范数的含义已经变成非典型程度；同时需要约定 T < 0 的边如何处理（截到 0 还是删掉），因为带符号输入上 T 的下界是 −1/3。另外，[docs/04 §3](../docs/04_选择度量与剪枝策略.md) 的范数窗口剪枝只在 τ > 0 时成立，在带符号输入上，不能剪枝的那一段会更长。logicle 输入要先实测 flowCore 在 0 处的输出，再决定是拒收还是重新居中。

第四，补上文献里的空白。调研没有找到任何一项研究检验过"行范数是否能提升聚类"，无论是 scRNA-seq、空间转录组、蛋白数据还是基础模型嵌入。CosTaL+ 的基准可以第一个回答这个问题。做法是：对每种预处理测 Spearman(‖x‖, log 总 UMI)、Spearman(‖x‖, 检出基因数)，以及 ‖x‖ 在细胞类型标签上的 η²；再在相同工作点下比较 cosine 边权和 Tanimoto 边权的 ARI/NMI。阳性对照用 Levine（C 类），阴性对照用单位化嵌入（E 类，与 [docs/01 §7](../docs/01_技术规划.md) 的人脸实验同理）。空间数据要分别用**空间域**标签和**细胞类型**标签评估，因为 Bhuva 的结果意味着幅度可能对前者有帮助、对后者有害。

第五，一个尚未验证的设计方向。T 只依赖 c 和 r，所以 r 不一定要来自选邻居所用的那个矩阵。docs/04 §6.1 已经把 `knn()` 的输出拆成 `idx`、`cos` 和 `norms`（[docs/04 §6.1](../docs/04_选择度量与剪枝策略.md)），`reweight()` 完全可以接受一个外部给定的幅度向量 m，比如原始总计数、细胞面积，或 arcsinh 丰度，再用 T = c/(m_a/m_b + m_b/m_a − c) 计算边权。这样可以在 shifted log 或 PCA 上选邻居，同时把"幅度代表什么"作为一个看得见、能写进论文方法部分的参数显式注入，而不是让它默默随预处理而变。

## 结论

过去三年的主流做法在几乎每个环节都把幅度往外推：kNN 图建在居中的 PCA 上；residual 模型显式消除深度；基础模型要么在输入端用秩编码丢掉库大小，要么在输出端单位化；连蛋白成像里的 Pixie 和 fastMNN 也在做逐行归一化。幅度仍然完整保留、含义也清楚的地方，主要只剩悬浮细胞术和成像质谱的逐通道 arcsinh，而这恰好是 CosTaL 原论文的主场。因此，CosTaL+ 的"+"在 scRNA-seq 和空间数据上不能直接沿用原论文的结论，需要用数据重新证明；而原版 scRNA 预处理的行范数主要记录深度，原论文在 scRNA-seq 上观察到的 Tanimoto 收益里有多少来自深度、多少来自生物学，目前无从判断。

更深一层的含义是：cosine 对行缩放不变，这使"选哪种归一化"在 CosTaL+ 里成了一个只作用于边权的旋钮。在测序型空间数据上，同一个幅度会帮助空间域识别、却伤害细胞状态识别；在成像型数据上，面积归一化后的幅度是密度，但其可靠程度不会超过分割。由此可见，"幅度是否有信息"没有通用答案，答案取决于用户要找的是什么结构。把幅度做成显式输入，并在元数据里报告它与 QC 协变量的相关，比为每个平台预设一种"正确的"归一化更诚实，也更容易在论文里讲清楚。
