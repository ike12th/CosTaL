# Mainstream preprocessing is rewriting what the row norm means

From 2023 to 2026, the default transform for count data (scRNA-seq, sequencing-based and imaging-based spatial transcriptomics) is still **scale by a size factor first, then take log(y/s+1)**. Scanpy uses `normalize_total` to scale each cell to the median depth and then `log1p`, Seurat v5 uses `LogNormalize` (scale.factor 1e4), and Bioconductor uses `logNormCounts` (log2, pseudocount 1). The output of this step is sparse and non-negative, but nearly every tool then **builds the kNN graph on 10–50 principal components**, which are dense and signed. The default for protein data (CyTOF, flow, spectral flow, IMC, MIBI) is **per-channel, uncentered arcsinh**: the CyTOF cofactor 5 is still hard-coded in CATALYST, Spectre and diffcyt, and no scaling is done before clustering. For CosTaL+, the key is the row norm. Tanimoto is identically cos/(r + 1/r − cos), so the only information it adds beyond cosine comes from the norm ratio r. Judged by this criterion: **of all inputs, arcsinh on protein data is the class whose row norm most cleanly equals "total marker abundance"**; for count data after shifted log, the row norm mixes the concentration of the expression profile with residual sequencing depth; after PCA, Pearson residuals or z-score, the row norm becomes "how far from the data center"; the embeddings of scGPT, UCE and SCimilarity are already unit-normalized, and on them Tanimoto degenerates to c/(2−c). The original CosTaL's scRNA-seq preprocessing does no `normalize_total` before `log1p`, and none of the current defaults does this. The resulting row norm mainly records sequencing depth, and Tanimoto amplifies this technical variation into edge-weight differences; adding one line, `normalize_total(target_sum=None)`, fixes it without losing sparsity. Spatial data shows the other side: library size varies with tissue structure (Bhuva 2024), and on small panels the result of total-count normalization in turn depends on how the panel was designed (Atta 2024). Here magnitude is both real signal and real confounder. The backend should therefore be dispatched by "input class", not by platform: zero-preserving, non-negative transforms go to the sparse inverted index; any centered representation, and all foundation-model embeddings, go to the dense backend.

## Every transform comes down to one question: what does r represent

Let c be the cosine and r = ‖a‖/‖b‖; then Tanimoto can be rewritten as **T = a·b/(‖a‖²+‖b‖²−a·b) = c/(r + 1/r − c)** (derived in this report; several of the research notes arrived at the same expression independently). Since r + 1/r ≥ 2, with equality only when the two vectors have equal length, for fixed cosine T is maximized at r = 1, and the larger the norm difference, the more T is pushed down. When r is identically 1, T = c/(2−c) is a strictly monotone function of c, and the neighbor ranking is exactly the same as for cosine. The denominator always satisfies ‖a‖²+‖b‖²−a·b ≥ (‖a‖²+‖b‖²)/2 > 0, so signed inputs never divide by zero, but the range of T widens from [0, 1] for non-negative inputs to **[−1/3, 1]** (−1/3 is attained at b = −a). The original CosTaL handles exactly these two sides separately: `find_communities` selects neighbors with the L2-normalized X, and `build_tani_graph` computes edge weights with the unnormalized X. On Levine_32dim the row norm spans a 5.8× range, and the original T differs from the degenerate form c/(2−c) by up to 0.516, showing that magnitude really does play a role ([docs/01 §2.2](../docs/01_technical_plan.md)).

The second corollary determines the role of "which normalization to choose" in CosTaL+: **cosine is invariant to positive per-row scaling**. Raw counts, total-count normalization, normalization by cell area or volume, the Xenium Onboard Analysis size factor, and CPM without log all amount to multiplying each row by a positive number, and therefore produce **exactly the same cosine kNN graph**. The neighbor set changes only when a nonlinear elementwise transform (log1p, sqrt) or a per-gene transform (z-score, Pearson residuals, PCA) follows. So the choice of linear normalization affects only the Tanimoto step; in effect it answers "what should the row norm represent". Below, the same three questions are asked of each data type: is the output sparse, can it be negative, and what biological meaning does the row norm still carry.

## scRNA-seq: shifted log is still the baseline, and the original CosTaL is missing a step

The three major ecosystems agree on the default in 2025–2026: divide by a size factor first, then take the log, with pseudocount 1. Scanpy's `normalize_total` defaults to `target_sum=None`, i.e. it scales each cell to **the median of total counts across all cells**, then `log1p` ([scanpy normalize_total](https://scanpy.readthedocs.io/en/stable/generated/scanpy.pp.normalize_total.html)). Seurat v5.6's `NormalizeData` defaults to `LogNormalize`, `scale.factor = 10000`, natural log ([Seurat NormalizeData](https://satijalab.org/seurat/reference/normalizedata)). scuttle's `logNormCounts` defaults to log2, `pseudo.count = 1`, and centers the size factors at 1; the OSCA example code estimates size factors with scran pooling ([scuttle logNormCounts](https://rdrr.io/bioc/scuttle/man/logNormCounts.html); [OSCA basic](https://bioconductor.org/books/release/OSCA.basic/normalization.html)). The other route is Pearson residuals. Scanpy's analytic version is still under `sc.experimental` as of 1.12.4, with θ = 100 and clipping to ±√n ([scanpy normalize_pearson_residuals](https://scanpy.readthedocs.io/en/stable/generated/scanpy.experimental.pp.normalize_pearson_residuals.html)). Seurat v5's `SCTransform` defaults to the v2 flavor; `scale.data` holds the centered residuals, with 3,000 variable genes by default, fed directly into PCA ([Seurat SCTransform](https://satijalab.org/seurat/reference/sctransform)). One more detail bears directly on CosTaL+'s determinism goal: only in Scanpy 1.12.4 (2026-08-27) was a bug fixed in which, with `target_sum=None`, **sparse and dense inputs computed different target_sum values** ([Scanpy release notes](https://scanpy.readthedocs.io/en/stable/release-notes/index.html)). "Same data, different storage format, different result" has actually happened in mainstream tools.

The reference benchmark in this area is still Ahlmann-Eltze & Huber (Nature Methods 2023). They compared 22 transforms from four families and concluded that **log(y/s + y0) plus PCA performs as well as or better than residual-based, latent-expression and count-based factor-model methods**; moreover, delta-method transforms preserve sparsity and use the least memory ([Ahlmann-Eltze & Huber 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10172138)). They relate the pseudocount to overdispersion (y0 = 1/(4α)): using CPM on cells with about 5,000 UMIs corresponds to α = 50, two orders of magnitude larger than typical single-cell data, while Seurat's 1e4 corresponds to y0 ≈ 0.5. Hence, **do not feed CPM into shifted log**. Two other results matter more for CosTaL+. First, on homogeneous RNA droplet data containing only technical variation, **the size factor remains a strong variance component even after scaling**. Second, rescaling each cell by "the sum over genes after transformation" neither removes the depth confounding nor improves kNN recall, and the authors explicitly advise against it (ibid.). The scverse best practices of Heumos et al. give task-specific advice: shifted log for dimensionality reduction and DE, scran for batch correction, analytic Pearson residuals for HVG selection and finding rare cells; they likewise warn against CPM ([Heumos et al. 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10066026)). No high-impact benchmark in 2024–2026 has overturned this conclusion. Ge et al. (PLOS ONE 2025) favor Dino for ARI clustering on 10x data ([Ge et al. 2025](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0335102)), but they compute ARI against labels, whereas Ahlmann-Eltze & Huber compare kNN overlap, so the two cannot be compared directly. The Pachter group's PFlog1pPF (a shifted CLR) claims better performance on the Ahlmann-Eltze & Huber kNN benchmark, but it is still a preprint without peer review ([bioRxiv](https://www.biorxiv.org/content/10.1101/2022.05.06.490859v4.full)).

It also needs to be clear what representation the kNN graph is built on. Scanpy's `pp.neighbors` defaults to 50 principal components when there are at least 50 variables, `metric='euclidean'`, `n_neighbors=15`, and switches to PyNNDescent approximate search for large data ([scanpy neighbors](https://scanpy.readthedocs.io/en/latest/api/generated/scanpy.pp.neighbors.html)). Seurat's `FindNeighbors` defaults to `dims = 1:10`, `k.param = 20`, annoy approximate search, and Euclidean distance ([Seurat FindNeighbors](https://satijalab.org/seurat/reference/findneighbors)). Heumos et al. state explicitly that clustering operates on a KNN graph computed on a low-dimensional representation ([Heumos et al. 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10066026)). The positive conclusion of Ahlmann-Eltze & Huber holds only within "a reasonable range of PCA dimensions", so **the original CosTaL, doing gene-level sparse cosine kNN on 2,000 HVGs, is already outside the setting in which shifted log was validated**. That does not mean the approach is wrong. merfish-tools builds the graph directly with `use_rep="X", metric="cosine"` for MERSCOPE panels of about 500 genes ([merfish-tools](https://merfish-tools.readthedocs.io/en/latest/notebooks/analyze_merscope_experiment.html)); the Bioconductor documentation of jvecfor also recommends cosine for log-normalized counts whose norm is inflated by library size ([jvecfor vignette](https://bioc-release.r-universe.dev/jvecfor/doc/jvecfor_vignette.Rmd)). But no single-cell benchmark in 2023–2026 has quantitatively compared cosine with Euclidean, nor gene-level graphs with graphs on PCA.

The actual steps of the original `pp(X, 'scrnaseq')` are `filter_cells(min_genes=200)` → `filter_genes(min_cells=3)` → `highly_variable_genes(n_top_genes=2000, flavor='seurat_v3')` → `log1p` → take the HVG subset ([clustering.py](../bench/reference/CosTaL-0.0.2.4/CosTaL/clustering.py)). Selecting HVGs with `seurat_v3` on raw counts is the correct usage ([scanpy highly_variable_genes](https://scanpy.readthedocs.io/en/stable/generated/scanpy.pp.highly_variable_genes.html)); the problem is that there is no size factor at all before `log1p`. The research found no 2023–2026 source supporting "no size factor, log1p directly" followed by clustering. Ahlmann-Eltze & Huber also treat y and y/s only as negative controls: on SUM149PT, the best method recovers 34 of 50 neighbors, the negative controls only 9; they did not test log(y+1) ([Ahlmann-Eltze & Huber 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10172138)). Mechanistically, when depth increases k-fold, each detected gene increases by about log k, and more genes are detected, so the row norm rises monotonically along both paths. And since log1p is not homogeneous, a change in depth also twists the vector's direction toward the 0/1 detection pattern, so **on this input cosine is not depth-invariant either**. Hicks et al. reported the same phenomenon: the detection rate correlates with the first two principal components, enough to split the same tumor into two clusters by batch ([Hicks et al.](https://www.biorxiv.org/content/10.1101/025528v4.full)). Hafemeister & Satija also saw depth-ordered gradients within clusters of log-normalized data ([Hafemeister & Satija 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6927181/)). On this input, the extra information Tanimoto adds is essentially technical: the edge between two cells of the same type, one deeply and one shallowly sequenced, is pushed down by r + 1/r, which can split clusters along depth or push shallowly sequenced cells to the edge of their cluster. The fix is one line: insert `normalize_total(target_sum=None)` (or scran size factors) before `log1p`. Neither depth normalization nor log changes zeros ([Lause et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8419999/)), so the sparse backend can be used as before.

| Transform (2023–26 status) | Sparse | Can be negative | What the row norm encodes |
|---|---|---|---|
| log1p(y), no size factor (**original CosTaL**; adopted by no current default) | Yes | No | Rises monotonically with depth: more genes detected, each nonzero entry up by about log k; depth also changes the direction |
| y/s (CPM, Seurat RC, no log) | Yes | No | L1 fixed; L2 equals expression-profile concentration, biased high at low depth |
| **log(y/s+1)** (Scanpy median / Seurat 1e4 / scuttle log2; **current default**) | Yes | No | Not normalized; concentration (a few markers dominating) mixed with residual depth, the two inseparable |
| log(CPM+1) | Yes | No | Dominated by the detection pattern; both Ahlmann-Eltze & Huber and Heumos advise against it |
| shifted log ÷ per-cell post-transform sum | Yes | No | L1 fixed, magnitude erased; Ahlmann-Eltze & Huber advise against it |
| SCT `data` = log1p(corrected counts) | Yes | No | Similar to shifted log, with less residual depth |
| Analytic Pearson residuals / SCT v2 `scale.data` | **No** (no zeros) | **Yes** | Deviation from the global average profile (in noise units), relative to the dataset |
| z-score (`ScaleData`, `sc.pp.scale`) | No | Yes | Diagonal Mahalanobis distance from the data center |
| PCA 30–50 dims (**the actual kNN input**) | No | Yes | Distance from the center in the PC subspace; if PC1 tracks depth, the norm contains depth |

Even with a size factor, the shifted-log row norm is not "biology only": it is a mixture of how concentrated expression is on a few markers (biological) and residual depth and detection rate (technical), which cannot be separated from counts alone. The research found no study quantifying the ratio of the two; CosTaL+ has to measure it itself.

## Spatial transcriptomics: library size is half tissue structure, half an artifact of measurement geometry

### Sequencing-based platforms: library size is itself a readout of tissue structure

Every vendor pipeline delivers a raw integer UMI matrix, including Space Ranger's 2/8/16 µm bins and v4 cell-segmentation output, Stereo-seq's GEF, and Slide-seq/Curio beads. The community default is global library-size scaling plus log1p. Seurat's Visium HD tutorials (both the per-bin and the per-segmented-cell versions) specify "standard log-normalization", replacing the SCTransform of the older Visium/Slide-seq tutorials ([Seurat Visium HD](https://satijalab.org/seurat/articles/visiumhd_analysis_vignette); [Seurat cell segmentation](https://satijalab.org/seurat/articles/visiumhd_analysis_cell_segmentations); [older spatial tutorial](https://satijalab.org/seurat/articles/spatial_vignette)). Stereopy's quick start is `normalize_total(target_sum=10000)` → `log1p` → `scale(max_value=10, zero_center=True)` → 30 principal components → Leiden ([Stereopy](https://stereopy.readthedocs.io/en/latest/Tutorials/SquareBin_Clustering.html)). Giotto's default "standard" method is scalefactor 6000, log2(x+1), then z-score once by gene and once by cell ([normalizeGiotto](https://giottosuite.com/reference/normalizeGiotto.html)). BANKSY goes its own way: `normalizeCounts(log = FALSE)` only scales to the mean library size and takes no log ([BANKSY](https://github.com/prabhakarlab/Banksy)). Spatial-domain methods also mostly consume log-normalized HVGs: STAGATE uses `normalize_total(1e4)` + `log1p`, SpaGCN uses `normalize_per_cell` + `log1p` ([STAGATE](https://stagate.readthedocs.io/en/latest/T1_DLPFC.html); [SpaGCN](https://github.com/jianhuupenn/SpaGCN/blob/master/tutorial/tutorial.md)). GraphST uses `scale(zero_center=False)`, which only divides and so stays sparse and non-negative, but it then converts the matrix to dense in `get_feature` ([GraphST preprocess.py](https://github.com/JinmiaoChenLab/GraphST/blob/main/GraphST/preprocess.py)).

The most important new evidence in this area comes from Bhuva et al. (Genome Biology 2024). Analyzing 25 samples across 4 platforms, they found that library size varies with cortical layers, white matter and tumor regions: after accounting for cell number with a Poisson model, **tissue region remains significant for library size (p < 2×10⁻³⁰⁸)**. For spatial-domain identification, sctransform was usually the worst, and "no normalization" (log raw counts) and scran the best. In the authors' words, spatial data "should not be specifically corrected for library size prior to analysis" ([Bhuva et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11025268/)). The subsequent SpaNorm (Genome Biology 2025) uses thin-plate splines to split spatially smooth variation into a "library-size-related" and a "library-size-unrelated" part, keeps only the latter, and outperforms common single-cell normalizations on 27 samples across 4 platforms; it outputs several forms, including `logpac`, `pearson` and `meanbio` ([SpaNorm](https://genomebiology.biomedcentral.com/articles/10.1186/s13059-025-03565-y); [SpaNorm vignette](https://bioconductor.org/packages/release/bioc/vignettes/SpaNorm/inst/doc/SpaNorm.html)). But the large iMeta 2025 benchmark (14 methods, about 600 datasets) concluded that "normalization was indispensable", and its recommended pipeline is library-size normalization, log, 3,000 spatially variable genes, no standardization, and 20 principal components ([iMeta 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12747554/)). The disagreement may stem from different evaluation targets. Bhuva used manually annotated spatial domains such as DLPFC, where library size is itself a distinguishing feature; iMeta averaged over methods that are mostly deep learning. This judgment is an inference; the research found no study that directly resolves the conflict.

On sparsity: Visium HD's 2 µm squares are tiled contiguously; an 8 µm bin has on average about 16× the UMIs of a 2 µm square, and is also 10x's recommended starting point ([Oliveira et al. 2025](https://www.nature.com/articles/s41588-025-02193-3)). A row with U UMIs has at most U nonzero genes, so the zero fraction is ≥ 1 − U/G (own derivation). Taking OSTA's CRC data as an example (G ≈ 18,085; the QC floor for 8 µm bins is a library size of 100): **an 8 µm bin just above the QC floor of 100 has at least 99.45% zeros (at least 98.3% at 300 UMIs), 2 µm is above 99.9%, and segmented cells (about 300–1,400 UMIs) are about 92–98%** ([OSTA Visium HD bin](https://bioconductor.org/books/release/OSTA/pages/seq-workflow-visium-hd-bin.html); [OSTA Visium HD segmentation](https://bioconductor.org/books/release/OSTA/pages/seq-workflow-visium-hd-seg.html)). These are mathematical lower bounds, not measured medians. Two tools are commonly used to go from bins to cells: bin2cell first destripes using row and column quantiles, then rescales each bin ([bin2cell](https://pmc.ncbi.nlm.nih.gov/articles/PMC11419951/)); ENACT assigns counts weighted by area or by transcripts ([ENACT](https://academic.oup.com/bioinformatics/article/41/3/btaf094/8063614)). Both produce non-integer counts, while the deconvolution step requires unnormalized raw counts ([cell2location](https://cell2location.readthedocs.io/en/latest/notebooks/cell2location_tutorial.html)).

### Imaging-based platforms: small panels make total-count normalization depend on panel design

Atta et al. (Genome Biology 2024) provide the mechanism. In a marker panel biased toward certain regions, over-represented genes inflate the library-size scaling factor of cells in those regions, depressing normalized expression there while inflating it elsewhere. The result: DE error rates of **up to 13% on MERFISH, and up to 30% on some simulated panels**; fold-change direction reversed across datasets in **up to 60%** of cases; SVG false negatives of up to 24% on CosMx. The effect shrinks when the panel grows to 5,000 genes, but it persists. Cell volume is independent of which genes are detected, so the authors list **volume normalization as the first choice**, with area as an alternative provided segmentation is reliable ([Atta et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11167774/)).

Vendor and community practice splits into several lines. The Xenium Onboard Analysis size factor is "total transcripts in the cell ÷ median over all cells"; clustering is done in a 10-dimensional PCA space, and UMAP uses `metric="pearson"` ([10x XOA](https://www.10xgenomics.com/support/software/xenium-onboard-analysis/latest/algorithms-overview/gex-secondary-analysis-algorithms)). Bruker's AtoMx recommends Total Counts and suggests Pearson residuals only for data under 500,000 cells; it uses 50 principal components, and UMAP uses Cosine distance ([Bruker blog](https://brukerspatialbiology.com/blog/tips-when-performing-cosmx-data-analysis-with-atomx-sip/)). Danaher's Scratch Space explicitly recommends staying on the linear scale and sets a floor of 20 on the total count used as the divisor, to limit the amplification of low-count cells, while acknowledging that this discards a real biological signal, namely that "cancer cells have more RNA overall" ([CosMx Scratch Space](https://nanostring-biostats.github.io/CosMx-Analysis-Scratch-Space/posts/normalization/index.html)). Seurat uses `SCTransform(clip.range = c(-10, 10))` for Vizgen and CosMx, followed by 30 principal components ([Seurat imaging spatial tutorial](https://satijalab.org/seurat/articles/seurat5_spatial_vignette_2)). Squidpy's Xenium and Vizgen tutorials are `normalize_total` + `log1p` + PCA + Leiden, mentioning only in a sentence of the text that "normalizing by volume is also possible" ([Squidpy Xenium](https://squidpy.readthedocs.io/en/stable/notebooks/tutorials/tutorial_xenium.html); [Squidpy Vizgen](https://squidpy.readthedocs.io/en/stable/notebooks/tutorials/tutorial_vizgen.html)). Only Bioconductor's OSTA actually uses an area size factor (`cell_area / median(cell_area)`) ([OSTA Xenium](https://lmweber.org/OSTA/pages/img-workflow-xenium.html); [OSTA CosMx](https://lmweber.org/OSTA/pages/img-workflow-cosmx.html)). Salas et al. (Nature Methods 2025) benchmarked 25 Xenium datasets; the best pipeline was "library-size normalization to 100, log, scaling, a 16-nearest-neighbor graph on all principal components, Louvain", and they found the normalization method to be one of the most critical factors in the entire processing pipeline ([Salas et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11978515/)).

Segmentation changes both the numerator (the counts assigned to the cell) and the denominator (the area). According to the measurements in the Proseg paper, vendor default segmentation leaves more than 20% of transcripts unassigned; on MERSCOPE the median T cell has only 81 transcripts and the median tumor cell 291; with default segmentation, 37% of DE results in the Xenium lung data are questionable, falling to 12% with Proseg ([Proseg](https://pmc.ncbi.nlm.nih.gov/articles/PMC11071468/)). Mitchel et al. (Nature Genetics 2026) found that the effects of segmentation errors often dominate the results of DE and ligand–receptor analyses ([Mitchel et al.](https://www.biorxiv.org/content/10.1101/2025.01.02.631135.full.pdf)). Contamination from neighboring cells is **additive**: it superimposes the neighbor's expression profile onto the vector, rotating its direction and changing its norm, and no per-cell scalar normalization (total-count or area) can remove it. This point is an inference, consistent with Danaher's statement that "adding covariates can only mitigate, not solve" the problem ([segmentation-error post](https://nanostring-biostats.github.io/CosMx-Analysis-Scratch-Space/posts/segmentation-error/index.html)). Sparsity can be estimated from per-cell counts and panel size: the CosMx 6K lymph node data average 461 genes per cell, about 92% zeros ([NanoString dataset page](https://nanostring.com/wp-content/uploads/2024/11/MK6578_CosMx_Human_Lymph_Node_FFPE_Dataset_webpage.html)); CosMx WTx has 627–1,677 genes per cell, about 91–97% zeros ([Bruker WTx](https://brukerspatialbiology.com/blog/moving-beyond-scrna-seq-the-power-of-cosmx-whole-transcriptome/); [AACR 2025 poster](https://nanostring.com/wp-content/uploads/2025/05/2779-AACR-2025_WTX_Cell_Assay_MerckBruker_Yi-Cui_MSedits_HS.pdf)). No public zero fractions were found for small 300–500-gene panels; extrapolating from about 100–400 counts per cell gives roughly 60–85%.

| Transform (typical use) | Sparse | Can be negative | What the row norm encodes |
|---|---|---|---|
| Raw counts (vendor exports; deconvolution; InSituType) | Yes: Visium HD 2 µm ≳99.9%, 8 µm about 98–99.5%; small panels about 60–85%; 5K/6K/WTx about 85–97% | No | Number of cells per bin, region (Bhuva), cell size, RNA content × capture/permeabilization/detection efficiency × segmentation contamination |
| Total-count linear (AtoMx Total Counts, XOA size factor, BANKSY `normcounts`) | Same as raw | No | L1 fixed; L2 = S·√Σp², i.e. concentration, **depends on panel design** |
| Area/volume linear (Atta's first choice) | Same as raw | No | Transcript density per µm², inherits segmentation error |
| log1p(total-count × L) (Seurat, Scanpy/Squidpy, Stereopy 1e4, Salas uses L = 100) | Same as raw | No | Residual depth/gene count + concentration |
| log(area-normalized + 1) (OSTA) | Yes | No | Compressed transcript density |
| SCT residuals, analytic Pearson, SpaNorm `pearson` | **Dense** | **Yes** (Seurat clips imaging data to ±10) | Deviation from the expected value; low-depth cells still carry depth |
| z-score (final step of the Giotto default, Stereopy `zero_center=True`, Salas's best pipeline) | Dense | Yes | Distance from the data center |
| GraphST `scale(zero_center=False)` | Yes | No | Same as log1p, only with genes reweighted |
| PCA, BANKSY PCs, GNN latent space | Dense | Yes | Distance from the data center |
| bin2cell / ENACT / Proseg expected counts | Yes (Proseg expected counts may have fewer zeros, unverified) | No (non-integer) | Cell size + residual capture differences |

For CosTaL+, what is special about spatial data is that magnitude is "informative" and "confounded" at the same time. On sequencing-based platforms, the row norm of raw counts or log raw counts varies with the number of cells per bin and with the region, so Tanimoto biases toward **spatial-domain** partitions, which is exactly what library-size normalization is meant to remove. On imaging-based platforms, the area-normalized row norm equals transcript density, the quantity closest to "RNA content", but it can be no more reliable than the segmentation.

## Protein data: clustering directly after arcsinh, without scaling, keeps magnitude most intact

In suspension cytometry, the CyTOF cofactor 5 is still the hard-coded default. CATALYST's `prepData` signature is `cofactor = 5`, and it accepts a per-channel vector ([CATALYST prepData.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/prepData.R)); Spectre's `do.asinh` also defaults to 5 ([Spectre do.asinh.R](https://github.com/ImmuneDynamics/Spectre/blob/master/R/do.asinh.R)); diffcyt says 5 is "suitable for CyTOF" ([diffcyt](https://rdrr.io/bioc/diffcyt/man/transformData.html)). The CytoNormPy benchmark and the Open Problems 2026 cytometry batch-integration benchmark also both use cofactor 5 for CyTOF ([CytoNormPy](https://onlinelibrary.wiley.com/doi/10.1002/cyto.a.24953); [Open Problems](https://openproblems.bio/benchmarks/cyto_batch_integration)). But Spectre's own documentation says "for most CyTOF channels, 15 is appropriate" ([Spectre docs](https://immunedynamics.io/Spectre/articles/data_transformation.html)). **CosTaL's 5/150/6000 triple exactly matches the values recommended in the cyCombine documentation** ([cyCombine](https://pmc.ncbi.nlm.nih.gov/articles/PMC8971492/)). These values are conventions inherited from one tool to the next; none of them has been independently validated as optimal. The 6000 for spectral flow has one more source: when Jaimes et al. compared Aurora with CyTOF in OMIQ, they chose 6000 "so that the negative population is unimodal around 0" ([Jaimes et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9790709/)). But for conventional and spectral flow, the accepted best practice is to **tune the cofactor per channel, in the range 10–10,000** ([den Braanker et al. 2021](https://www.frontiersin.org/journals/immunology/articles/10.3389/fimmu.2021.768113/full)). Tools such as OTflow and flowVS can estimate per-channel cofactors automatically ([OTflow](https://onlinelibrary.wiley.com/doi/full/10.1002/cyto.a.24491)), but the research found no new 2023–2026 method that supersedes them. Using a single cofactor across spectral data means some channels are over-compressed and others under-compressed, which changes which markers dominate the row norm. Another pitfall is logicle: it is FlowJo's display default and also the default `transformFunction` of FlowSOM's `ReadInput` (though the default is `transform = FALSE`) ([FlowSOM](https://github.com/SofieVG/FlowSOM/blob/master/R/0_FlowSOM.R)). By definition, a data value of 0 does not map to 0 under logicle, so all cells share a positive offset vector, and the cosine origin thereby loses its meaning of "no signal". The research did not verify this by measurement with flowCore; it should be measured once before deciding whether to reject logicle input or re-center it.

On negative values, mainstream CyTOF pipelines keep them by default. diffcyt explains where they come from: the instrument software by default performs background subtraction and randomizes the integer counts ([diffcyt](https://rdrr.io/bioc/diffcyt/man/transformData.html)). Papoutsoglou et al. measured that maximal randomization lowers the ARI of metaclustering from 0.83 to 0.72 ([Papoutsoglou et al. 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC7027760/)). CATALYST's `compCytof` uses NNLS compensation by default, so its output is naturally non-negative ([compCytof.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/compCytof.R)). Spectre's `reduce.noise` (subtract 1, replace negatives with small noise) is an optional step explicitly labeled "experimental". The original CosTaL has a corresponding optional function, `minus_1_normalize_arcsinh`: subtract 1, clip at 0, fill all-zero rows with 1.0, then arcsinh ([clustering.py](../bench/reference/CosTaL-0.0.2.4/CosTaL/clustering.py)). Filling all-zero rows with 1.0 avoids an undefined cosine, but places those cells in the same uniform direction. Measured on this repository's Levine_32dim data: 27.0% of the raw values are negative, in the range [−0.291, 0), with no exact zeros; after arcsinh(x/5) the negatives fall in [−0.058, 0) and **account for only about 0.01% of each cell's squared norm**, and clipping to 0 lowers the nonzero fraction from 100% to 73% ([Levine_32dim_notransform.fcs](../bench/data/Levine_32dim_notransform.fcs)). So on CyTOF, whether to keep negatives is a question of density and performance, not of semantics. For flow and spectral flow after compensation or unmixing, negative values can reach hundreds to thousands in raw units and are distributed symmetrically on both sides of the negative population, so clipping piles up mass at 0. This point is an inference, not measured.

Not scaling before clustering is also mainstream practice. FlowSOM defaults to `scale = FALSE`, and CATALYST's `cluster()` sends the `exprs` assay straight into FlowSOM ([CATALYST cluster.R](https://github.com/HelenaLC/CATALYST/blob/devel/R/cluster.R)); 0–1 percentile scaling is used only for heatmaps. Batch correction is done on the arcsinh scale, and its output stays on that scale: CytoNorm 2.0 no longer requires technical replicate samples ([CytoNorm 2.0](https://pure.eur.nl/en/publications/cytonorm-20-a-flexible-normalization-framework-for-cytometry-data/)); cyCombine uses z-scores or ranks only as intermediates for SOM co-clustering, does ComBat on the original expression scale, and clips the result to the input range ([cyCombine](https://pmc.ncbi.nlm.nih.gov/articles/PMC8971492/)). In other words, **CosTaL's protein preprocessing is aligned with the defaults of CATALYST, Spectre and FlowSOM**, and the row norm is total marker abundance.

Spatial proteomics pipelines are more fragmented, falling roughly into two groups: those that keep magnitude and those that erase it. The Bodenmiller IMC pipeline is: steinbock takes the **mean** over each cell's pixels, CATALYST does spillover compensation with NNLS, then **asinh(x/1)**, followed by clustering without scaling ([steinbock](https://github.com/BodenmillerGroup/steinbock/blob/main/docs/cli/measurement.md); [IMCDataAnalysis](https://bodenmillergroup.github.io/IMCDataAnalysis/read-data.html); [phenotyping](https://github.com/BodenmillerGroup/IMCDataAnalysis/blob/main/08-phenotyping.Rmd)). The independent OPTIMAL study titrated the cofactor between 0.1 and 150, concluded that 1 is optimal, and recommends a subsequent z-score to remove batch effects ([OPTIMAL 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC10952805/)). Note that the post-integration clustering in the IMC book is done on the fastMNN embedding, and fastMNN defaults to `cos.norm = TRUE`, which L2-normalizes each cell first ([batchelor fastMNN.R](https://github.com/LTLA/batchelor/blob/master/R/fastMNN.R)). MIBI's ark pipeline is total intensity ÷ cell area, then arcsinh(100·x) ([ark](https://github.com/angelolab/ark-analysis/blob/main/src/ark/segmentation/marker_quantification.py)). Pixie, by contrast, first normalizes each pixel to sum to 1 and then scales by the 99.9th percentile; the authors explicitly acknowledge that this **cannot discover phenotypes distinguished by high versus low expression of the same marker** ([Pixie](https://pmc.ncbi.nlm.nih.gov/articles/PMC10393943/)), which is direct evidence that "per-row normalization erases level information". CODEX's SPACEc z-scores each marker by default, following the recommendation of Hickey 2021 ([SPACEc](https://github.com/yuqiyuqitan/SPACEc/blob/master/src/spacec/preprocessing/_general.py); [Hickey et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8415085/)). CyCIF's scimap uses log1p plus per-image piecewise scaling to [0, 1], anchored at GMM gates ([scimap](https://scimap.xyz/Functions/pp/rescale/)). spatialproteomics (Nature Methods 2026) defaults to arcsinh(x/5) ([spatialproteomics](https://github.com/sagar87/spatialproteomics/blob/main/spatialproteomics/pp/utils.py)). The benchmarks contradict one another: Hickey recommends z-score, while UniFORM points out that on right-skewed data z-score compresses low-intensity points toward 0 and weakens the mutual exclusivity between markers ([UniFORM 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12539234/)). No benchmark has evaluated whether the row norm itself is useful.

How each transform changes the meaning of the row norm can be measured directly on Levine. In the table below, "abundance" is defined as Σ asinh(max(x,0)/5), and ρ is the Spearman correlation of the cell's row norm with it ([Levine_32dim_notransform.fcs](../bench/data/Levine_32dim_notransform.fcs), 265,627 cells × 32 markers):

| Transform | Nonzero fraction | Negative fraction | ρ(norm, abundance) | ρ(norm, raw sum) |
|---|---|---|---|---|
| asinh(x/5), negatives kept (CosTaL default) | 1.000 | 0.270 | 0.790 | 0.762 |
| asinh(max(x,0)/5), clipped | 0.730 | 0 | 0.790 | 0.762 |
| asinh(x/1) (IMC convention) | 1.000 | 0.270 | 0.968 | 0.544 |
| asinh(x/150) (flow cofactor applied to CyTOF) | 1.000 | 0.270 | 0.297 | 0.992 |
| asinh(x/5) → per-marker z-score | 1.000 | **0.651** | 0.502 | −0.061 |
| asinh(x/5) → 1/99 percentile clipping + min-max | 0.990 | 0 | 0.919 | 0.456 |
| asinh(x/5) → per-cell L1 normalization | 1.000 | 0.270 | **−0.783** | 0.173 |

There are three findings. First, the cofactor decides what the norm listens to: with a small cofactor, close to log, the norm reflects "how many markers are on"; with a large cofactor, close to linear, the norm is dominated by the few brightest channels. Second, after z-score, the correlation between norm and abundance drops to 0.50, while the correlation with "distance from the mean" is 0.82, so **the meaning changes from abundance to atypicality**; moreover, a uniformly dim cell and a uniformly bright cell get vectors of opposite sign. Third, after per-cell normalization, the norm is anticorrelated with abundance and measures concentration.

## Foundation models: depth is erased at the input; at the output, embeddings are either unit-normalized or have norms nobody has explained

Input encodings fall into four families. The first is per-cell rank or quantile encoding: Geneformer first scales within-cell expression by the gene's expression level across the whole corpus, then ranks ([Geneformer](https://huggingface.co/ctheodoris/Geneformer)); Nicheformer first normalizes to 10,000, then divides by the nonzero mean computed separately for each technology, then ranks, with sequence length 1,500 ([Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)); scGPT bins by **quantiles** of the cell's nonzero values, with 0 in a bin of its own ([scGPT preprocess.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/preprocess.py)); State SE takes the top 2,048 genes by log fold rank ([Virtual Cell Challenge](https://huggingface.co/blog/virtual-cell-challenge)). This family of encodings is invariant to monotone within-cell transforms, so library size is discarded at the input; scGPT's zero-shot embedding path accordingly skips `normalize_total` and `log1p` altogether ([cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)). The second family projects continuous log values to vectors with an MLP: CellFM uses log1p plus an MLP ([CellFM](https://pmc.ncbi.nlm.nih.gov/articles/PMC12092794/)); scPRINT uses log2(x+1) plus an MLP, with an additional total-count token ([scPRINT](https://pmc.ncbi.nlm.nih.gov/articles/PMC12003772/)); scFoundation appends two depth tokens, including log10(total count), after `log1p(x/Σx·1e4)` ([scFoundation get_embedding.py](https://github.com/biomap-research/scFoundation/blob/main/model/get_embedding.py)). The third is UCE, which samples genes weighted by expression and requires raw counts as input ([UCE](https://github.com/snap-stanford/UCE)). The fourth is TranscriptFormer, which models raw counts generatively, with counts truncated at 30 by default ([TranscriptFormer](https://github.com/czi-ai/transcriptformer)). One controlled comparison found that hard binning is worse on every metric, and soft binning is best ([Sadalski, ICLR 2026 workshop](https://iclr.cc/virtual/2026/10013720)).

At the output, every model produces **dense floating-point vectors that can be negative**, with dimensions ranging from 128 (SCimilarity) to 1,280 (UCE); CellFM's hidden width is 1,536, and scFoundation's default concatenation has 4d dimensions. The most critical dividing line for CosTaL+ is whether the embedding is unit-normalized:

| Model | Cell embedding | Dims | Unit-normalized in the official code? |
|---|---|---|---|
| scGPT | `<cls>` output | 512 | **Yes**, divided by the L2 norm ([cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)) |
| UCE | CLS after MLP decoding | 1,280 | **Yes**, `normalize` is called in `forward()` ([UCE model.py](https://github.com/snap-stanford/UCE/blob/main/model.py)) |
| SCimilarity | MLP bottleneck layer | 128 | **Yes**, "unit length normalized" ([SCimilarity](https://pmc.ncbi.nlm.nih.gov/articles/PMC11864978/)) |
| Geneformer V2-316M | CLS by default; mean pooling in "cell" mode | 1,152 | No ([emb_extractor.py](https://huggingface.co/ctheodoris/Geneformer/blob/main/geneformer/emb_extractor.py)) |
| scFoundation | Default concatenation [depth token, T token, max-pool, mean-pool] | 4d | No ([get_embedding.py](https://github.com/biomap-research/scFoundation/blob/main/model/get_embedding.py)) |
| Nicheformer | Mean of gene tokens, excluding context tokens | 512 | Not mentioned in the paper ([Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)) |
| CellFM / TranscriptFormer / State SE / scPRINT | CLS or mean pooling | Not all documented | Not documented |

For unit-normalized embeddings, r ≡ 1, and Tanimoto is just a fixed convex transform of cosine; the neighbor set and ranking are unchanged. For embeddings that are not unit-normalized, nobody has studied what the norm represents, and the only direct evidence is negative: Nicheformer excludes context tokens when pooling precisely because the output norm of the modality tokens is high and pulls the embedding toward the modality ([Nicheformer](https://pmc.ncbi.nlm.nih.gov/articles/PMC12695652/)). scFoundation's default concatenation directly includes the embedding of the depth token, so its norm is likely correlated with library size; moreover, the four blocks have different scales, so cosine on the concatenation will be dominated by the block with the largest norm. This point is an inference. In practice, the CELLxGENE Census tutorial calls `sc.pp.neighbors(adata, use_rep="scgpt")` directly without specifying a metric, i.e. it uses Euclidean ([Census tutorial](https://chanzuckerberg.github.io/cellxgene-census/notebooks/api_demo/census_embedding.html)). For unit-normalized embeddings, Euclidean, cosine and Tanimoto select the same neighbor sets; for non-normalized embeddings they do not. The research found no source that discusses this difference.

Independent benchmarks rate zero-shot embeddings poorly. Kedzierska et al. found that HVGs beat Geneformer and scGPT on every metric ([Kedzierska et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12007350/)). Hou et al. compared 13 models in 2026: on gastric tissue data PCA reaches an ARI of 0.65, and only SCimilarity exceeds it, at 0.68; on spatial data, no model beats PCA in the zero-shot setting ([Hou et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC12803055/)). Liu et al., across 1,607 datasets, concluded that performance depends strongly on the task and that no method consistently leads ([Liu et al. 2026](https://www.biorxiv.org/content/10.64898/2026.06.18.733285)). The only winner, SCimilarity, happens to be trained with a triplet loss and to output unit-normalized embeddings, which suggests that embeddings designed for distance comparison are better suited to kNN graphs; but this is only a correlation within a single benchmark. One more point concerns CosTaL+'s determinism: scGPT's official embedding path randomly samples genes when a cell has more than about 1,200 nonzero genes, and ties during binning are also broken randomly ([cell_emb.py](https://github.com/bowang-lab/scGPT/blob/main/scgpt/tasks/cell_emb.py)), so without a fixed seed two embedding runs are themselves inconsistent.

## For CosTaL+: dispatch the backend by input class, and make "what magnitude represents" an explicit parameter

Putting the sections above together, all inputs fall into five classes. The class, not the platform, determines both the backend choice and whether Tanimoto is meaningful:

| Input class | Examples | Sparse | Can be negative | Row-norm meaning | Backend | Role of Tanimoto |
|---|---|---|---|---|---|---|
| A Zero-preserving, non-negative, high-dimensional | scRNA shifted log, SCT `data`, log1p(raw); sequencing-based spatial bins/cells; log1p or area-normalized 5K/6K/WTx panels | Yes (Visium HD 2 µm ≳99.9%; 5K+ panels about 85–97%) | No | Concentration + residual depth; RNA content/density when raw or area-normalized | Sparse inverted index | Informative but confounded by depth/segmentation; needs to be measured |
| B Zero-preserving, non-negative, low-dimensional | 300–500-gene imaging panels | Moderate (about 60–85% zeros, estimated) | No | Same as A | Dense may be cheaper; to be tested | Same as A |
| C Low-dimensional, uncentered abundance | CyTOF/flow/spectral arcsinh, IMC asinh(x/1), MIBI ark, percentile or min-max scaling | No (Levine 100% nonzero) | CyTOF: yes, but tiny; flow/spectral: not negligible | **Total marker abundance** (the cofactor decides what dominates) | Dense | **Matches CosTaL's design intent; strongest evidence** |
| D Centered, signed | PCA, Pearson residuals, SCT `scale.data`, z-score, non-unit-normalized FM embeddings | No | Yes | Distance from the data center; meaning of FM norms unknown | Dense | Semantics change; T can be negative |
| E Already row-normalized | scGPT/UCE/SCimilarity, fastMNN `cos.norm`, Pixie, double z-score, L1/L2-normalized inputs | Depends on input | Depends on input | Constant, or reflects only the shape of the profile | Dense | T ≡ c/(2−c); no new information |

First, the scRNA-seq default path. `compat="paper"` must keep reproducing `log1p(raw)` bit for bit; that contract is already settled ([docs/04 §0.0](../docs/04_selection_metric_and_pruning.md)). Beyond that, a scRNA preset of `normalize_total(target_sum=None)` + `log1p` should be offered, and the two compared with the experiments in docs/04 §5. If the new preset wins, then under versioning policy (b), changing the default requires a major version bump ([docs/04 §6.5](../docs/04_selection_metric_and_pruning.md)). Both presets are zero-preserving and non-negative and both go to the sparse backend, so switching between them does not affect the backend design. A CPM preset should not be offered.

Second, backend dispatch. The current rule in [docs/06 §5.2](../docs/06_cross_platform_and_determinism.md) looks only at storage format, nonzero fraction and dimensionality; two more signals should be added: whether negative values are present, and whether the columns are centered. Any column-centered input is effectively dense and should go straight to the dense backend, with no need to test a threshold. Pearson residuals in the raw gene space are a memory trap: 1 million cells × 2,000 genes × float32 is about 8 GB (own estimate), and Lause et al. already reported 4.5 GB on PBMC ([Lause et al. 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8419999/)). Users should be advised to do PCA first, or simply to use shifted log. 300–500-gene imaging panels sit near the sparse/dense boundary, which makes them a good case for measuring the `auto` threshold.

Third, write input diagnostics into the output metadata. Record at least four items: the coefficient of variation of the row norm, the column means and column standard deviations, the negative fraction, and the nonzero fraction. When the row-norm CV ≈ 0, generalize the short-circuit rule in [docs/04 §0.1](../docs/04_selection_metric_and_pruning.md) from `normalize=L2` to "the input is already unit-normalized", and emit a single warning that Tanimoto is equivalent to a monotone transform of cosine. When the columns are already centered, warn that the meaning of the row norm has become atypicality; a convention is also needed for edges with T < 0 (clip to 0 or delete them), because on signed inputs the lower bound of T is −1/3. In addition, the norm-window pruning in [docs/04 §3](../docs/04_selection_metric_and_pruning.md) holds only for τ > 0, and on signed inputs the segment that cannot be pruned will be longer. For logicle input, first measure flowCore's output at 0, then decide whether to reject it or re-center it.

Fourth, fill the gap in the literature. The research found no study that has tested "whether the row norm improves clustering", whether for scRNA-seq, spatial transcriptomics, protein data or foundation-model embeddings. CosTaL+'s benchmark can be the first to answer this question. The approach: for each preprocessing, measure Spearman(‖x‖, log total UMI), Spearman(‖x‖, number of detected genes), and the η² of ‖x‖ over cell-type labels; then compare the ARI/NMI of cosine edge weights and Tanimoto edge weights at the same operating point. Use Levine (class C) as the positive control and unit-normalized embeddings (class E, by the same reasoning as the face experiment in [docs/01 §7](../docs/01_technical_plan.md)) as the negative control. Spatial data should be evaluated separately with **spatial-domain** labels and with **cell-type** labels, because Bhuva's results imply that magnitude may help the former and hurt the latter.

Fifth, a design direction that has not yet been validated. T depends only on c and r, so r need not come from the matrix used to select neighbors. docs/04 §6.1 already splits the output of `knn()` into `idx`, `cos` and `norms` ([docs/04 §6.1](../docs/04_selection_metric_and_pruning.md)), so `reweight()` could perfectly well accept an externally supplied magnitude vector m, such as raw total counts, cell area or arcsinh abundance, and compute edge weights as T = c/(m_a/m_b + m_b/m_a − c). This makes it possible to select neighbors on shifted log or PCA while injecting "what magnitude represents" explicitly, as a visible parameter that can be written into a paper's methods section, rather than letting it change silently with the preprocessing.

## Conclusion

Over the past three years, mainstream practice has pushed magnitude out at nearly every step: kNN graphs are built on centered PCA; residual models explicitly remove depth; foundation models either discard library size at the input with rank encoding or unit-normalize at the output; even Pixie and fastMNN in protein imaging do per-row normalization. The places where magnitude is still fully preserved and its meaning clear are mainly per-channel arcsinh in suspension cytometry and imaging mass cytometry, which happens to be the home turf of the original CosTaL paper. Therefore, on scRNA-seq and spatial data, the "+" in CosTaL+ cannot simply carry over the original paper's conclusions; it has to be proven again with data. And because the row norm of the original scRNA preprocessing mainly records depth, there is currently no way to tell how much of the Tanimoto gain the original paper observed on scRNA-seq comes from depth and how much from biology.

The deeper implication: because cosine is invariant to row scaling, "which normalization to choose" becomes, in CosTaL+, a knob that acts only on the edge weights. On sequencing-based spatial data, the same magnitude helps spatial-domain identification but hurts cell-state identification; on imaging-based data, the area-normalized magnitude is a density, but it can be no more reliable than the segmentation. Hence "is magnitude informative" has no universal answer; the answer depends on what structure the user is looking for. Making magnitude an explicit input, and reporting its correlation with QC covariates in the metadata, is more honest than presetting one "correct" normalization for each platform, and it is also easier to explain in a paper.
