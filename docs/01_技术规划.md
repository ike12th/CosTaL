# CosTaL+ 技术规划（v0，2026-09-16）

> 本文是**规划**，不是实现记录。每条判断都标注了依据；被实测推翻的要照实改，
> 不要保留已经证伪的说法。

## 1. 三条决定成败的判断

### 1.1 瓶颈只有一个地方：kNN 建图

CosTaL 三步中：

- **Tanimoto 精修**是 `O(边数)`，且能复用 kNN 阶段已算出的 `a·b` 与 `‖·‖²`
  （原论文明确指出这点）；
- **Leiden** 近线性，通常不是瓶颈；
- **kNN 建图**吃掉绝大部分时间。

**所以重写的火力几乎全部投在 kNN**，其余两步先用成熟实现。
→ **前置动作**：先 profile 现有 Python 版，用数字确认这条判断；推翻了就改本文。

### 1.2 kNN 的实质 = 分块矩阵乘 + top-k 选择

matmul 有极成熟的加速路径（Apple: Accelerate 自动走 AMX；x86: MKL/OpenBLAS + AVX2/512）。
**容易被忽视的是 top-k**：matmul 优化完之后，朴素排序会成为新瓶颈。
→ top-k 用堆 / introselect + SIMD，这部分自己写才有价值。

### 1.3 "AI 硬件加速"要说实话：ANE 用不上

Apple Neural Engine **没有公开的通用 GEMM 接口**，只能通过 CoreML 跑模型图，
无法用于任意 kNN 计算。

可行的加速面：

| 平台 | 可行 | 不可行 |
|---|---|---|
| Apple Silicon | Accelerate/AMX（BLAS 已在用）、Metal 计算着色器、NEON | ANE |
| x86 + N卡 | CUDA、AVX2/AVX-512 | — |

→ 路线图只写 GPU/SIMD/BLAS，**不要写 ANE**。

## 2. 分层设计

```
CosTaL+ (Rust + PyO3/maturin)
├── 前置层   归一化策略（L2 / 无 / 幅度携带质量）、可选降维（PCA / 随机投影）
├── kNN 层   ① 精确：p-L2knng 重写（剪枝上界；科研可复现性需要）
│            ② 近似：HNSW / IVF（大规模走这条）
│            两条实现落在同一个 trait 后面，调用方一行切换
├── 精修层   Tanimoto 边权，与 cosine 融合成**同一趟** kernel
│            （复用 a·b 与 ‖·‖²，避免二次遍历边表）
├── 社区层   Leiden（先绑 leidenalg；profile 证明它是瓶颈后再自己写）
└── 后端     CPU: BLAS + SIMD(NEON/AVX) · GPU: Metal(Apple) / CUDA(N卡)
```

### 2.1 为什么 Rust 而非 C++

- maturin 出 wheel、cargo 管依赖；交叉编译到 `macos-arm64` 与 `linux-x86_64`
  正好覆盖目标机器；
- 并行 kNN 里内存安全省下大量调试时间。

代价：BLAS / Metal 绑定要自己接——活是有限的，可接受。

### 2.2 幅度语义（与人脸线共用的实验）

Tanimoto `T = a·b / (‖a‖² + ‖b‖² − a·b)` 在 **L2 归一化向量上退化**为
`T = c / (2 − c)`，是 cosine 的严格单调变换：邻居排序不变，**只改变边权形状**
（对弱边打压更狠：c=0.9→0.818，c=0.5→0.333，c=0.3→0.176）。

→ 所以 Tanimoto 的价值在**边权**，不在邻居选择。
→ 若让幅度携带真实信息（例如按质量/置信度缩放向量而不归一化），
  `‖a‖²+‖b‖²` 项才真正干活。**这是待验假设，不是结论**，两种模式都要能跑、能对比。

## 3. 交付形态

1. **Python wheel**（maturin）——`pip install` 即可用，供 `nas-manager` 等调用方；
2. **独立 CLI**——不写 Python 也能跑；
3. **C ABI**——将来可嵌入其它宿主。

wheel 需覆盖 `macos-arm64`、`linux-x86_64`。

## 4. 验证（决定它是不是 "CosTaL+" 而不是"又一个聚类库"）

两组基准，都要**一键复现**：

1. **单细胞**：在原论文用过的数据集上复跑，报告精度（与原版对比）+ 加速比；
2. **人脸**：`nas-manager` 的人脸 embedding，证明跨领域可用。

没有这两组数字，就只是个库。

## 5. 与 nas-manager 的关系

- CosTaL+ 是**独立仓库、独立生命周期**；
- nas-manager 通过 pip 装 wheel，**只依赖公开 API**；
- nas-manager 先用 `hnswlib` + `leidenalg` 把人脸轨跑通并**把接口定下来**，
  CosTaL+ 成熟后换实现即可。

→ 两条线互不阻塞：人脸线不等 Rust；写 Rust 时手上已有真实调用方与真实数据当基准。

## 6. 尚未决定的事（不留暗示）

1. 精确 kNN 是否真的需要——取决于科研复现场景的权重，待定；
2. Metal 后端做到什么程度（只做 matmul，还是连 top-k 一起下放）；
3. Leiden 是否自己写——等 profile 数字；
4. 降维是否进默认管线（PCA 会改变相似度语义，需实验支撑）；
5. 版本/API 稳定性策略（何时锁 1.0）。

## 7. 实证发现（2026-09-16，来自 nas-manager T85）

在人脸 embedding 上完整跑了一遍 CosTaL 管线（151 张脸 / 8 个身份 / hnswlib + igraph + leidenalg），
得到一条**可推广的边界条件**：

> **Tanimoto 精修的收益取决于"幅度是否携带信息"。**

- **幅度有信息时**（单细胞计数 / 流式强度）：`‖a‖²+‖b‖²` 项真正参与判别，
  这是原论文"区分方向相同但幅度不同"的来源，也是 CosTaL 的价值所在。
- **幅度被抹平时**（L2 归一化向量，如 ArcFace 人脸 embedding）：
  `T = c/(2−c)` 退化为 cosine 的**严格单调变换**（导数 `2/(2−c)² > 0`），
  邻居排序不变，只是换了阈值刻度。第②步成为空操作。

实测佐证：`normalized × cosine, t=0.25` 与 `normalized × tanimoto, t=0.15`
给出同一操作点（`T=0.15 ↔ c=0.2609`），指标几乎一致
（0.933/0.701/0.960 vs 0.935/0.675/0.960）。

### 7.1 对基准设计的影响（修订 §4）

人脸数据**不应**作为"跨领域也更好"的展示案例，而应作为**阴性对照**：
证明当幅度无信息时，CosTaL **退化为 cosine 基线且不劣化**。
真正的性能主张仍须来自幅度有信息的数据（单细胞）。

### 7.2 另外两条实测观察

1. **resolution 是最值钱的旋钮**（在人脸数据上）：Leiden 的 resolution
   1.0 → 准确率 0.664，2.0 → 0.846。默认分辨率会把不同身份并进同一社区。
2. **"小 k 保质量"这条卖点在人脸数据上验证不了**：8 个身份彼此分得太开，
   阈值 ≥0.25 时 k=5..30 逐行同解。要验证这条卖点，基准必须用
   **类间边界模糊**的数据集——这对 §4 的基准选型是硬要求。

### 7.3 顺带的工程事实

- `onnxruntime` 的 CoreML EP 在 M1 Pro 上与 CPU EP 输出**逐张完全一致**
  （cosine 1.00000），但 12 张样本上**没有加速**（2.73s vs 2.75s）。
  推理加速不要想当然，要测。
