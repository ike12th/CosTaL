# 选择度量与剪枝策略（v0，2026-09-20）

> 回答两个问题：
> 1. cosine 选择（+Tanimoto 边权）和 Tanimoto 选择，要不要做成两个版本？
> 2. 怎么写才不牺牲速度、不牺牲可验证性？
>
> **答案：不是两个版本，是一个内核 + 两个比较器 + 一个数据布局决定。**

---

## 0. 先厘清：三个正交的旋钮

原版 CosTaL 已经把其中一个做成参数了（`method='tani'|'jaccard'|'cosine'`），
但它只管**边权**。完整的设计空间是三维：

| 旋钮 | 取值 | 影响 | 原版 |
|---|---|---|---|
| `normalize` | L2 / 原始幅度 | 相似度语义 | 选邻居时 L2，算边权时原始 |
| `select` | cosine / tanimoto | **邻居集** | 恒为 cosine |
| `weight` | tanimoto / cosine / jaccard | **边权** | 可选，默认 tanimoto |

**已发表的 CosTaL = (normalize=L2, select=cosine, weight=tanimoto) 这一格。**
这一格必须是默认值，而且必须逐条复现——这是"精度不退"的契约。
其余格子一律 opt-in。

### 0.0 默认值是一份契约，不只是两个旋钮

"不传参数 = 已发表的 CosTaL"要成立，被钉住的**不止 select 和 weight**。
下面每一条都会改变输出，都必须进默认值、都必须有回归测试：

| # | 被钉住的东西 | 原版的值 | 不钉住会怎样 |
|---|---|---|---|
| 1 | `select` / `weight` | cosine / tanimoto | 邻居集或边权变 |
| 2 | **归一化的两面性** | 选邻居用 L2 归一化，算边权用**原始范数** | 边权退化成 `c/(2−c)`（docs/02 §4） |
| 3 | **图对称化公式** | `S + Sᵀ − S∘Sᵀ`（模糊并集），**不是** `(S+Sᵀ)/2` | 边权系统性偏小，社区结构变 |
| 4 | 自环与 k 的语义 | 去自环；k 不含自身 | 每行多/少一条边 |
| 5 | Leiden 参数 | `RBConfigurationVertexPartition`,<br>`resolution=0.8`, `n_iterations=10` | 簇数直接变 |
| 6 | tie-break | 见 §4.1 | 同一输入两次跑结果不同 |

第 3 条尤其容易漏：原版 `build_graph` 里那行
`csr = csr + csr.T - csr.multiply(csr.T)` 上面还留着一行注释掉的
`(csr + csr.T) * 0.5`——**两者不等价**，抄错了指标会悄悄掉一点点。

### 0.1 一个必须显式处理的退化格

当 `normalize=L2` 时 `A=B=1`，`T = c/(2−c)` 是 cosine 的严格单调变换，
于是 **`select=tanimoto` 完全等价于 `select=cosine`**（docs/01 §2.2 / §7）。

这不是 bug，是数学事实。但如果不处理，用户会报"tanimoto 选择没效果"。
所以：

```
if normalize == L2 and select == tanimoto:
    → 短路成 cosine，并 warn 一次，说明原因
```

**顺带白拿一个测试 oracle**：这条恒等式可以写成 property test——
`(L2, tanimoto, *)` 的输出必须与 `(L2, cosine, *)` **逐条相同**。
Tanimoto 比较器的代数一旦写错，这条断言立刻炸。见 §4。

## 1. 决定一：一个泛型内核，编译期单态化

比较器**不能**用运行时 enum / dyn 分发。整个内层循环的预算按
**约 1 个周期/候选**估，插一个不可预测的分支就可能翻倍。

> **更正（2026-10-12）**：原文写的是"1.2 个周期/候选（docs/03 §2 实测）"，
> 但 docs/03 里没有这个测量，git 历史里也找不到出处。**这是估算，不是实测**；
> 真实数字由阶段 A 的 bench 给出。结论（比较器必须静态分发）不受影响。

```rust
trait Selector {
    /// 每行预计算的常量。cosine: 只有 τᵢ；tanimoto: cᵢ 与 cᵢ·Aᵢ
    type RowState: Copy;
    fn row_state(norm_sq: f32, tau: f32) -> Self::RowState;
    /// 列块级的保守标量阈值，见 §2
    fn tile_threshold(st: Self::RowState, col_norm_sq_min: f32) -> f32;
    /// 罕见通过后的精确复核
    #[inline(always)]
    fn exact_pass(st: Self::RowState, cand_norm_sq: f32, sim: f32) -> bool;
}
```

在调用入口 `match` 一次，之后全程静态分发：

```rust
match select {
    Select::Cosine   => run_blocked::<CosineSel>(...),
    Select::Tanimoto => run_blocked::<TanimotoSel>(...),
}
```

`#[inline(always)]` + 单态化 ⇒ 编译器生成两份特化循环，内层**零分支**。
代价是二进制里多一份代码（几 KB），换来零运行时开销。

## 2. 决定二：保守标量阈值 + 罕见路径精确复核

### 2.1 问题

Tanimoto 的判据 `d > cᵢ·(Aᵢ + Bⱼ)` 里有个 `Bⱼ`——**阈值随候选变化**。
直接写就是内层多一次 FMA（`d − cᵢ·Bⱼ > cᵢ·Aᵢ`），top-k 那一半贵 25–60%。
能省。

### 2.2 做法

对一个列块，取块内最小范数平方 `B_min`，定义**保守标量阈值**：

```
θᵢ = cᵢ · (Aᵢ + B_min)      ← 每行每块算一次，不在内层
```

因为 `Bⱼ ≥ B_min`（`cᵢ ≥ 0` 时；`cᵢ < 0` 时换成 `B_max`，见 §2.4），有 `θᵢ ≤ cᵢ(Aᵢ+Bⱼ)`，
所以**真正该通过的候选一定能通过 θᵢ**——只有假阳性，没有假阴性。

内层循环于是和 cosine 一模一样，**1 次比较**：

```
if tile[i][j] > θᵢ {          // 99.99%+ 在这里被拒（约 1 周期，待实测）
    if Sel::exact_pass(st, B[j], tile[i][j]) {   // 罕见路径，随便多贵
        heap_insert(...);
        θᵢ = Sel::tile_threshold(st, B_min);     // τᵢ 变了，重算
    }
}
```

**结论：Tanimoto 选择的内层循环成本 ≈ cosine 选择。** 代价只是列块的
`B_min` 一个标量，和罕见路径上多一次乘加。

### 2.3 让保守阈值变紧的关键：按范数排序

`θᵢ` 的松紧取决于列块内范数的跨度。所以——

> **数据布局决定：预处理时把行按 ‖x‖ 升序重排，最后用置换表映射回原序。**

列块内范数几乎相同 ⇒ `B_min ≈ Bⱼ` ⇒ 保守阈值几乎是精确阈值，假阳性极少。

这个排序是**一鱼两吃**的：它同时让 §3 的范数窗口剪枝成为可能。
一次 `O(N log N)` 的排序（26 万行约 20 ms），买两样东西。

### 2.4 一个正确性护栏：按 τᵢ 的符号选 B_min / B_max

> **已按实测改写（2026-10-12）。** 原文写的是"arcsinh 变换后的流式/质谱数据都非负，
> 所以 `select=tanimoto` 入口校验输入非负"。前提是错的：Levine_32dim 全量
> `arcsinh(x/5)` 之后 **27.0% 的元素为负、99.8% 的行含负值**（最小约 −0.058，
> docs/06 §5.1）。照原文实现，主基准会被直接拒掉，§5 的实验跑不起来；
> 而且原版 CosTaL 本来就在这些带负值的数据上算 Tanimoto，拒绝负值反而破坏复现。

Tanimoto 的取值范围是 `[−1/3, 1]`，所以 `1+τᵢ > 0`，`cᵢ = τᵢ/(1+τᵢ)` 与 `τᵢ` 同号。
保守阈值只需按 `cᵢ` 的符号选边界：

```
cᵢ ≥ 0：θᵢ = cᵢ·(Aᵢ + B_min)     ← Bⱼ ≥ B_min ⇒ θᵢ ≤ cᵢ(Aᵢ+Bⱼ)
cᵢ < 0：θᵢ = cᵢ·(Aᵢ + B_max)     ← Bⱼ ≤ B_max ⇒ θᵢ ≤ cᵢ(Aᵢ+Bⱼ)
```

两种情况都只有假阳性、没有假阴性，选择结果仍然精确。这个分支在**每行每块**
判断一次（τᵢ 只在罕见路径上变），不进内层循环，§2.2 的成本结论不变。

→ **不校验输入符号。** 实际上只有堆还没填满时 τᵢ 才可能为负：填满之前取 Tanimoto 的
下界 −1/3，此时 `cᵢ = −1/2`，`θᵢ = −(Aᵢ+B_max)/2 ≤ −‖a‖‖b‖ ≤ dᵢⱼ` 恒成立，
等价于"全部放行"，正是该有的行为。

## 3. 决定三：范数窗口剪枝——Tanimoto 专属的免费红利

由 `d = ‖a‖‖b‖·cos` 和 `ρ = ‖b‖/‖a‖`：

```
T ≥ τ   ⟺   cos ≥ c·(ρ + 1/ρ) ,   c = τ/(1+τ)
```

因为 `cos ≤ 1`，得到一条与方向完全无关的剪枝规则：

```
ρ + 1/ρ > (1+τ)/τ   ⟹   该候选无论方向如何都够不到 τ，整块跳过
```

τ=0.5 时门槛 `ρ+1/ρ > 3`，即 **ρ > 2.618 或 ρ < 0.382**。

这条只在 **τᵢ > 0** 时成立（推导里用了 `c > 0`）。堆刚开始填、τᵢ 还 ≤ 0 时
不剪（见 §2.4）——带负值的数据（如 Levine）上这一段会更长，剪枝率要实测。

行已按范数排序（§2.3）⇒ 每个 query 只需扫一个**连续的范数窗口**，
窗口外的列块**连 matmul 都不用做**。

**在 Levine_32dim 上这条会真的咬**：实测行范数跨度 2.949–17.233（5.8 倍，
docs/02 §4）。实际剪枝率取决于 τᵢ 收敛到多少，要测（§5）。

> 注意这条**只对 `select=tanimoto` 成立**。`select=cosine` 时范数不参与判据，
> 窗口剪枝无效——cosine 路线要靠锥形/聚类上界（docs/03 §3，阶段 D）。
> 两条剪枝机制落在同一个 `KnnIndex` trait 后面，互不干扰。

## 4. 决定四：三层正确性网

速度可以慢慢调，**邻居集错了整个项目就没意义了**。三层，从便宜到贵：

| 层 | 内容 | 规模 | 频率 |
|---|---|---|---|
| **L1 恒等式** | `(L2, tanimoto) ≡ (L2, cosine)` 逐条相同 | N≤2000 | 每次 CI |
| **L2 暴力对照** | Rust 里一份不分块、不剪枝的朴素实现，所有 (normalize × select × weight) 组合逐条比对 | N≤20000 | 每次 CI |
| **L3 原版对照** | 默认格 `(L2, cosine, tanimoto)` 与原版 CosTaL 的邻居集逐条比对 | Levine 子集 | 每次发版 |

L3 的现实约束：原版的 `p_knng` 是 Linux x86-64 二进制，本机跑不了
（docs/02 §1.1）。但 CosTaL 在非 Linux 上的回退路径 `bc()` 走
`phenograph.bruteforce_nn`，**本机可跑**，可以当 L3 的替身；
真正的 `p_knng` 对照放进 Linux CI。

> **待核（2026-10-12）：**
>
> 1. **索引起始。** 原版调用 `p_knng` 时传了 `-writeZidx`（按 0 起始写出），
>    读回后却又做了 `columns - 1`（注释 "bug in L2knng"）。若二进制真按 0 起始写，
>    原版每个邻居都偏一位；但那样会出现 −1，scipy 建稀疏矩阵时直接报错，
>    论文的跑数过不去——所以多半是二进制实际按 1 起始写、那个 −1 是对的。
>    **这关系到默认值契约，必须用黄金输出钉死**：在 NAS（x86-64）或 CI 的
>    ubuntu runner 上跑 `p_knng_Linux`（docs/02 §1.1 附记）。
> 2. **`bc()` 只能替身默认格。** `bc(method='cosine')` 里 `d` 没去掉自身那一列
>    （`idx` 去了），权重与边数对不上；而且 `d` 是 `cdist` 给的**距离**（升序），
>    直接当边权会把远近弄反。默认的 `method='tani'` 不受影响。
> 3. **与 `p_knng` 的差异只可能出在近似并列上**（docs/06 §1.3），差多少用黄金输出量。

### 4.1 确定性 tie-break（必须先定，否则前三层全部失效）

matmul 必须用 f32（docs/03 §3③），相对误差 ~1e-7，在第 k 名附近会出现并列。
规则写死：

```
相似度相等时，取列索引较小者。
```

注意排序（§2.3）会打乱原始索引——**tie-break 必须按原始索引判定，
不是按排序后的位置**，否则 k 值或线程数一变结果就不一样。

> **补充（2026-10-12）：tie-break 作用在 f64 精排之后的值上**（docs/06 §1）。
> f32 只负责全量粗选出 k+m 个候选，最终名次由 f64 固定顺序重算的相似度决定。
> 否则不同平台的矩阵库舍入不同，会让第 k 名附近的顺序翻转——那不是精确相等，
> tie-break 管不到。

## 5. 实验设计：这个"+"到底值不值

`select=tanimoto` 是 CosTaL 没做过的事。论文给 Tanimoto 的理由是
"区分方向相同但幅度不同"——**这个理由对邻居选择的适用性不亚于对边权**，
而现在只用在了边权上。这是可以直接验的。

Levine_32dim，14 个人工门控群体，报 ARI / NMI：

| | `weight=cosine` | `weight=tanimoto` |
|---|---|---|
| `select=cosine` | 纯 cosine 基线 | **已发表的 CosTaL** |
| `select=tanimoto` | 新 | 新 |

全部在 `normalize=原始幅度` 下跑（L2 下第二行会退化，见 §0.1）。
副产品：§3 范数窗口的实际剪枝率、以及 `select` 换掉后邻居集变了多少。

**三种可能的结局，都要照实写**：
1. `select=tanimoto` 更好 → 这是 CosTaL+ 的方法学贡献；
2. 持平 → 说明幅度信息在边权里已经用尽了，**这本身也是个干净的结论**，
   而且省掉一个旋钮；
3. 更差 → 说明 cosine 的邻居集 + Tanimoto 的边权形状是个有意思的组合，
   原版的选择是对的。**照实写，不要藏。**

## 6. API 形状

### 6.1 分成"贵的一步"和"免费的一步"

kNN 是唯一贵的部分；边权是 `(cos, ‖a‖, ‖b‖)` 上的纯变换，`O(N·k)`，
Rust 里约 10 ms。所以把它们拆开，让调用方能在**同一份 kNN 上**换边权：

```python
knn = costal_plus.knn(X, k=10, select="cosine", normalize="l2")
#   → knn.idx (N,k) int32 · knn.cos (N,k) f32 · knn.norms (N,) f32

e1 = costal_plus.reweight(knn, "tanimoto")   # ~10 ms
e2 = costal_plus.reweight(knn, "cosine")     # ~10 ms
e3 = costal_plus.reweight(knn, "jaccard")    # 例外，见 6.3

knn5 = costal_plus.truncate(knn, k=5)        # 取每行前缀，~0 成本

costal_plus.build_graph(X, k=10)             # 一步到位的便捷入口
costal_plus.find_communities(X, k=10)        # 端到端（等 cluster 层）
```

收益：§5 的 2×2 实验从"跑四次 kNN"降到**跑两次 kNN、出六组边权**；
nas-manager 的人脸线也能在一份 kNN 图上反复扫 weight 与 resolution
（docs/01 §7.2：resolution 是最值钱的旋钮，正是要反复扫的东西）。

`truncate()`（2026-10-12 补入；docs/05 §2.3 已经在引用它）：扫 k 也一样，
按 k_max 算一次，更小的 k 直接截前缀。它成立的前提是每行按
(f64 相似度降序, 原始索引升序) 全序排好（docs/06 §1），
这时前缀**就是**更小 k 的精确答案，不是近似。

### 6.2 默认值

```python
knn(X, k=10, select="cosine", normalize="l2", backend="exact")
build_graph(X, k=10, select="cosine", weight="tanimoto",
            normalize="l2", backend="exact", symmetrize="fuzzy_union")
```

**不传任何可选参数 ⇒ 输出必须与已发表的 CosTaL 逐条相同**（§0.0 的六条全部钉住）。

### 6.3 两条必须写进文档的约束

1. **reweight ≠ 换选择。** 重算边权只改边上的数，改不了图里有哪些边。
   `select=cosine` + `weight=tanimoto`（已发表的 CosTaL）与
   `select=tanimoto` + `weight=tanimoto` 是**两张不同的图**——
   Tanimoto 判据里的 `Bⱼ` 会把范数大的候选推出前 k
   （docs/02 §4 实测两者排序不一致，Pearson r=0.780）。
2. **`weight=jaccard` 不在免费档。** tanimoto↔cosine 互转只用到
   `(cos, ‖a‖, ‖b‖)`，都在手上；Jaccard 要算邻居的邻居的交集，
   得对 kNN 结果再走一遍，`O(N·k²)` 量级
   （原版 `map_jaccard` 为此开了 multiprocessing Pool）。

### 6.4 为什么不做成两个函数/两个二进制

1. 贵的东西（matmul、分块、并行、图组装、IO）**100% 共用**，
   分开就是同一份代码维护两遍；
2. §4 的三层验证**本来就要对所有组合跑**，分成两个入口只是多一层调度；
3. 最关键的：**未来的剪枝后端要同时服务两种选择度量**
   （§3 的范数窗口给 tanimoto，锥形界给 cosine）。
   如果在选择度量这一层就分叉，剪枝层会被迫写两遍。
   分叉点应该在**比较器**（十几行），不在**版本**。

### 6.5 兼容逃生舱（对应 docs/01 §6 第 5 条）

**已定（2026-09-20）：路线 (b)。** 默认值**允许**改——如果 §5 的实验证明
别的组合更好，就该让 `pip install` 的人直接拿到更好的东西，而不是把它
永远关在 flag 后面。但两条硬约束：

1. **改默认值必须跳主版本号**（0.x → 1.0 → 2.0）。别人写
   "we used costal-plus v1.2" 时，主版本号就足以确定默认语义。
2. **`compat="paper"` 从第一天存在、永不移除。** 复现路径显式且永不断。

所以从第一天起就提供：

```python
costal_plus.knn(X, k=10, compat="paper")   # 显式锁定 bbad157 的全部语义
```

这样即使将来默认值因为 §5 的实验结论而改变，**复现路径永远存在且显式**。
